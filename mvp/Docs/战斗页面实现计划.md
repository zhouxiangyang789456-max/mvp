# 战斗页面实现计划

## 目标

第一阶段在 Unity 中实现战斗页面的可交互原型，重点完成战斗主界面、等距地图展示、指挥官信息面板、卡牌栏、小地图、队形切换与基础部署交互。当前项目 `Assets` 基本为空工程，因此本阶段会先建立场景、UI 结构、数据骨架和可验证的交互闭环。

指挥官选择页面作为战斗页的前置入口纳入规划。第一版先做最小可用选择流程：选择伊莲娜后点击“出征”进入 `BattleScene`，战斗页从选择结果读取指挥官数据。

## 指挥官选择页面设计

指挥官选择页参考 `指挥官选择页面/ui演示.png`。第一版只需要保证流程可跑通，不要求所有指挥官卡都有完整内容。

### 页面布局

- 背景：使用 `指挥官选择页面/背景.png`。
- 左上：返回按钮。
- 顶部中间：标题“选择指挥官”。
- 左侧：三个摘要面板，分别显示指挥官、特性、初始兵种。
- 中央：当前选中指挥官详情面板。
- 底部：6 个指挥官卡槽。
- 右下：绿色“出征”按钮。

### 第一版交互

- 默认未选择时，“出征”按钮置灰或点击无效。
- 点击指挥官卡后：
  - 左侧“指挥官”摘要显示名称。
  - 左侧“特性”摘要显示该指挥官特性。
  - 左侧“初始兵种”摘要显示步兵、坦克。
  - 中央详情面板显示头像、名称、生命和特性。
  - 卡槽显示选中高亮。
- 点击“出征”：
  - 保存选择结果到 `BattleStartContext`。
  - 加载 `BattleScene`。
  - 战斗页读取 `BattleStartContext.SelectedCommander` 并刷新指挥官面板。

### 第一版指挥官数据

先只配置一个完整可用指挥官：

```text
Id: commander_elena
Name: 伊莲娜
MaxHealth: 100
CurrentHealth: 86
Traits: 勇敢、谨慎、鼓舞、坚韧
StartingUnits: 2 Infantry, 1 Tank
```

其余 5 个卡槽可以先显示空卡或锁定态，后续再补真实指挥官。

### 数据传递方式

第一版使用静态上下文即可，简单可靠：

```csharp
public static class BattleStartContext
{
    public static CommanderDefinition SelectedCommander;
}
```

后续如果需要存档、跨场景回放或多人配置，再改为 `ScriptableObject` 或存档数据对象。

## 队形系统设计

### 基础规则

- 指挥官拥有一个部署范围，默认 `5x5`。
- 部署范围以绿色边框或半透明绿色格子显示。
- 士兵默认悬浮显示在所在地形格上方。
- 点击指挥官头像框后显示部署范围。
- 点击某个士兵后，该士兵颜色明显变化，表示已选中。
- 鼠标移动到可部署格时显示目标格预览。
- 点击可部署格后，士兵移动到该格。

### 队形类型

```text
Vertical   竖向：士兵沿列方向排布
Horizontal 横向：士兵沿行方向排布
Square     方形：士兵尽量排列为紧凑矩形
```

### 推荐脚本职责

- `FormationType`：队形枚举。
- `FormationController`：根据当前队形和士兵数量计算目标格偏移。
- `DeploymentRangeView`：显示和隐藏绿色部署范围。
- `DeployableCellView`：单格高亮、悬停、点击。
- `UnitDeploymentController`：处理点击指挥官、选择士兵、移动士兵。

### 数据结构草案

```csharp
public enum UnitType
{
    Infantry,
    Tank
}

public enum FormationType
{
    Vertical,
    Horizontal,
    Square
}

public sealed class UnitDefinition
{
    public UnitType Type;
    public string DisplayName;
    public int Cost;
    public int MoveRange;
    public int VisionRange;
    public int ActionPoints;
    public bool CanCaptureCity;
}

public sealed class UnitRuntimeData
{
    public string Id;
    public UnitDefinition Definition;
    public Vector2Int GridPosition;
    public bool IsSelected;
}

public sealed class CommanderRuntimeData
{
    public string Id;
    public Vector2Int GridPosition;
    public int DeployRangeSize = 5;
}
```

## 地图实现方案

### 第一版

- 使用 `SpriteRenderer` 或 `Tilemap` 搭建等距格子。
- 地图尺寸先定为 `12x10`。
- 每个格子保存坐标、地形类型、是否可部署、是否被占用。
- 摄像机使用正交模式，固定等距视角。
- 基础地形优先使用 `地形2d资源（斜）/基础地形` 下的平原、森林、山地、丘陵、沙漠、水域等资源。
- 第一版测试地图参考 `地图展示.png`，先使用基础地形块搭出类似分布：中央大面积平原，左侧森林，前侧沙漠/沙滩，边缘浅水和海洋，后侧丘陵、山地、雪山。
- 第一版不使用道路资源。道路相关处理延期到第二阶段，避免尺寸不统一影响地图搭建和战斗交互验证。

### 测试地图布局参考

测试地图以 `地图展示.png` 为视觉目标，不要求逐格完全一致，但要保留地形层次：

- 中央：大面积平原，作为主要部署与战斗区域。
- 左侧：森林区域，形成明显地貌边界。
- 前侧和右前侧：沙漠、沙滩、浅水、海洋递进。
- 后侧：丘陵过渡到山地，最远端放置雪山。
- 边缘：海洋 tile 包围地图边缘，形成岛屿棋盘观感。
- 道路：第一版省略，不放置斜向道路。

推荐先制作一个手写测试关卡数据：

```text
Assets/Scripts/Battle/TestBattleMapData.cs
```

用二维数组描述地形类型，便于快速调整地形分布和验证格子坐标。

### 地形资源预处理

地形资源目录：

```text
D:/prounity/mvp/地形2d资源（斜）
├── 基础地形
│   ├── 平原.png
│   ├── 森林.png
│   ├── 山地.png
│   ├── 丘陵.png
│   ├── 沙漠.png
│   ├── 浅水.png
│   ├── 海洋.png
│   └── ...
└── 道路
    ├── 基础.png
    ├── 公路.png
    ├── T字路口.png
    ├── 十字路口.png
    ├── 转弯公路.png
    └── ...
```

基础地形可作为标准 tile 的规格参考，先确定统一的：

- 画布尺寸：所有 tile 输出到同一像素宽高。
- 中心点：统一使用格子中心作为 pivot。
- Pixels Per Unit：所有地形 sprite 使用相同 PPU。
- 排序点：地形格、道路覆盖层、单位、选中高亮分别使用稳定的 sorting layer/order。

道路系列目前存在宽度和尺寸不一致，不能直接作为格子 tile 使用。该工作放到第二阶段。预处理策略：

- 将道路图放入统一尺寸透明画布中，保持道路视觉居中。
- 不拉伸道路主体，避免道路宽度变形。
- 输出为单独的道路覆盖层 sprite，而不是替换基础地形。
- 道路 tile 与基础地形 tile 使用同一坐标格，但渲染在基础地形之上。
- 道路类型按连接关系命名：`Road_Straight`、`Road_Corner`、`Road_T`、`Road_Cross`、`Road_Highway` 等。
- 每个道路 sprite 需要记录方向：例如 `NorthSouth`、`EastWest`、`NorthEast`、`NorthEastSouth`。

推荐增加一个编辑器预处理工具：

```text
Assets/Editor/Battle/TerrainSpriteNormalizer.cs
```

工具职责：

- 扫描外部地形资源或导入后的 `Assets/Art/Battle/Terrain/Raw`。
- 读取图片尺寸，生成尺寸报告。
- 按标准 tile 画布输出修正后的 sprite。
- 为道路资源补透明边距，而不是缩放到铺满。
- 输出到 `Assets/Art/Battle/Terrain/Processed`。
- 生成 `TerrainTileCatalog`，供地图生成器按地形类型引用。

第一版可以先人工确认标准尺寸，再让工具做批量补边。后续如果道路需要更精细地贴合地形，可以再增加每张道路的 offset 配置。

## 风险与待确认

- 原型中的金色边框和装饰件目前是整图展示，后续若要做到高度还原，需要切图或重绘九宫格边框。
- 地图地形素材较多，第一版只接入基础地形；道路必须经过统一画布和 pivot 修正后再进入第二阶段。
- 队形系统里“指挥官自由画范围”的描述需要进一步确认：第一版建议先固定为 `5x5`，后续再做可拖拽调整部署范围。
- 士兵是否允许重叠、是否受地形限制、是否需要路径动画，第一阶段先按“不可重叠、瞬移或简单插值移动”处理。
- 单位系统资料里兵种较多，第一版只实现步兵和坦克；其余单位暂不进入数据表，避免过早扩展。
- 指挥官选择页第一版只做伊莲娜完整流程，其余 5 个卡槽可以先占位；后续再补更多指挥官、特性和初始兵种组合。
