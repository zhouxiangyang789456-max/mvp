# Blender MCP 工作规则

## 适用范围

本项目中，凡是需要新建或实质修改以下内容，必须使用 Blender MCP 在 Blender 中完成：

- 3D 游戏单位、角色、敌人、建筑、武器、道具和场景模型。
- 骨骼、蒙皮、约束、形态键和角色绑定。
- 待机、移动、攻击、受击、死亡等关键帧动画。
- 需要修改网格、材质、UV、骨骼或动画数据的美术资产。

不得用手写 `.blend` 文件、伪造 MCP 执行结果或仅靠 Unity 基础几何体冒充最终 3D 资产。Unity 基础几何体只允许用于不涉及正式美术资产的临时玩法验证。

## 开始前检查

1. 确认 Blender 已打开，并启用了 Blender MCP 插件。
2. 确认 Blender MCP Socket 使用 `127.0.0.1:9876`。
3. 确认当前 Codex 任务已经加载 Blender MCP 工具。
4. 先通过 Blender MCP 读取场景、对象或当前文件状态，再进行修改。
5. 如果 MCP 工具未加载或端口未连接，停止 3D/动画制作，明确告诉用户打开 Blender，并从 `D:\prounity\mvp` 新建 Codex 任务；不得声称已经完成 Blender 操作。

## 标准使用流程

1. 明确资产需求：用途、风格、尺寸、面数、材质、动画列表和 Unity 中的使用方式。
2. 通过 Blender MCP 检查当前场景，确认不会覆盖用户已有对象。
3. 使用 Blender MCP 提供的对象操作或 Blender Python 执行工具创建、修改模型。
4. 对复杂任务分阶段完成：模型、UV/材质、骨骼蒙皮、动画、导出。
5. 每个阶段后读取对象信息，并使用视口截图检查外观、比例和穿模情况。
6. 保存可编辑的 `.blend` 源文件，再通过 Blender MCP 导出 Unity 可用资产。
7. 最后报告生成文件、对象名称、动画名称、导出参数和仍需人工确认的事项。

调用工具时应以当前任务实际暴露的 Blender MCP 工具名称和参数结构为准。常见能力包括读取场景信息、读取对象信息、执行 Blender Python 以及获取视口截图；调用前先检查工具说明，不得猜测不存在的工具或参数。

## 模型规范

- 使用清晰、稳定且不重复的英文对象名、网格名、骨骼名和材质名。
- 以米为单位制作，保持合理真实比例；导出前应用必要的旋转和缩放。
- 将原点放在便于 Unity 定位的位置。角色和地面单位通常以脚底中心为原点。
- 清理重复顶点、错误法线、孤立几何体和未使用数据。
- 根据资产用途控制面数，不为了细节无意义地提高几何复杂度。
- 需要贴图时整理 UV，避免无意重叠，并使用 Unity 可识别的贴图文件。

## 骨骼与动画规范

- 骨骼层级、命名和朝向必须保持一致；修改已有绑定前先检查 Armature 和权重。
- 每个独立动画使用独立 Action，并采用清楚的英文名称，例如 `Idle`、`Move`、`Attack`、`Hit`、`Death`。
- 循环动画必须检查首尾连续性；非循环动画必须检查结束姿态。
- 导出前检查关键帧范围、帧率、根骨运动和 NLA/Action 状态。
- 交付时列出每个动画的名称、帧范围、是否循环，以及是否包含 Root Motion。

## 导出到 Unity

- 默认优先使用 FBX；只有在项目明确采用 glTF 等格式时才更换格式。
- FBX 导出方向按 Unity 约定设置为 `Forward: -Z Forward`、`Up: Y Up`，并检查缩放。
- 模型、动画和贴图导出到 Unity 项目的 `Assets` 下合适目录，不写入 `Library`、`Temp` 或包缓存目录。
- 对动画只导出需要的骨骼和 Action，避免把测试对象、相机、灯光或无关动画带入 Unity。
- 导出后验证文件确实存在，并在 Unity 导入后检查比例、材质、骨骼和动画片段。

## 修改与安全

- 修改已有 `.blend` 文件前先确认目标文件和对象；重要文件优先另存版本。
- 不删除用户已有对象、动画、材质或源文件，除非用户明确要求。
- Blender MCP 断开、执行报错或截图无法验证时，应报告真实状态并停止继续叠加修改。
- Blender MCP 只负责 Blender 资产制作；游戏逻辑、Unity C# 脚本和普通项目配置不强制使用 Blender MCP。
