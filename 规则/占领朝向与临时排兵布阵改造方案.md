# 占领、编队朝向与临时排兵布阵改造方案

## 1. 文档目标

本方案用于改造战斗中的三个相关行为：

1. 点击城市或兵工厂后，当前激活指挥官的全部存活单位一起移动到建筑附近，而不是只移动少量可占领单位。
2. 占领速度由到位并参与占领的步系单位数量决定，步系单位越多，占领越快。
3. 编队正面朝向玩家点击的目标位置；“排兵布阵”改为一个临时战斗指令，玩家下达移动、攻击或占领命令后，该临时阵型立即失效。

本方案继续遵守“玩家只控制当前指挥官编队，不直接控制单兵”的总原则。

## 2. 现状与问题

### 2.1 当前占领流程

当前 `CommanderGroupCommandController.CommandCaptureBuilding`：

- 只筛选带有 `CanCaptureBuilding` 标签的成员。
- 最多选择 4 名成员。
- 只给这些成员分配建筑相邻外圈格。
- 其他编队成员留在原地。

当前 `BuildingCaptureController`：

- 只统计建筑相邻外圈上的可占领单位。
- 每方最多统计 4 人。
- 占领倍率为 1 人 `1.0x`、2 人 `1.5x`、3 人及以上 `2.0x`。

因此现在的表现不是“整支部队靠近并包围建筑”，而是少量步系单位脱离编队。

### 2.2 当前朝向流程

- 单位移动时只根据下一段路径调用 `FaceDirection`。
- 编队运行时没有稳定保存并使用“本次点击方向”。
- 阵型槽位主要按固定世界坐标计算，没有完整地围绕目标方向旋转。

因此部队虽然能移动到目标区域，但阵型正面不一定朝向鼠标点击位置。

### 2.3 当前阵型流程

- 战斗开始后会锁定 `FormationLayoutSnapshot`。
- 普通移动继续使用锁定的槽位偏移。
- 战斗中“调整阵型”确认后，新的自定义槽位仍会被后续移动长期保留。

这与新的需求“排兵布阵是一次临时指令，点击移动后阵型失效”冲突。

## 3. 目标交互

### 3.1 点击建筑

玩家点击未归属己方的城市或兵工厂时：

1. 读取当前激活的指挥官编队。
2. 取消该编队当前攻击、移动、重整或旧占领命令。
3. 将建筑点击格记录为本次命令目标，并计算编队朝向。
4. 为全部存活成员计算建筑附近的合法目标格。
5. 先批量验证所有成员的目标格、预留和路径；全部成功后再同时移动。
6. 步系单位优先分配到建筑紧邻外圈，作为占领贡献者。
7. 非步系单位分配到外圈之外的支援格，不贡献占领进度，但必须跟随整支编队靠近建筑。
8. 所有必要的步系单位到位后开始累计占领进度；其余成员仍在抵达支援位时，不阻止已经到位的步系单位开始占领。
9. 建筑归属改变后，清除占领状态，编队进入 `Idle`，不自动恢复已经失效的旧阵型；单位停留在建筑周边各自位置，直到玩家下达下一条命令。

如果无法为全部存活成员找到完整合法位置，整条占领命令失败，任何成员都不得先行。

### 3.2 占领速度

只统计同时满足以下条件的单位：

- 存活。
- 属于正在执行该建筑占领命令的编队。
- 带有 `Infantry` 与 `CanCaptureBuilding` 标签。
- 已到达分配给自己的建筑紧邻占领格。
- 当前没有被击退、死亡或改派到其他命令。

> 实现注意（贡献者绑定是本次改造跨模块耦合最大的点）：`BuildingCaptureController` 目前是全局扫描所有带 `CanCaptureBuilding` 的单位，不感知“命令/编队”。改为命令绑定后，它需要通过 `UnitData.CommanderGroupId` 反查 `CommanderGroupRegistry` 中编队的 `CaptureCommandRuntime`，校验该命令指向本建筑、且单位当前格等于其分配格，再计入贡献者；为每方建立“命令 → 贡献者”映射，避免全局 tag 扫描误计。
>
> 敌方路径：现在敌方单位“碰巧站在建筑旁”就会自动占领。严格绑定命令后，需确认敌方 AI 是否通过 `CommandCaptureBuilding` 下发命令；若敌方依赖“碰巧站环”逻辑，应保留“无命令时按 tag + 紧邻格”的回退规则，否则敌方将无法占领。

建议将占领速度改为可配置的递减增益：

```text
CaptureRate = BaseCaptureRate × (1 + 0.5 × (ValidInfantryCount - 1))
```

默认效果：

| 有效步系单位 | 占领倍率 |
| --- | ---: |
| 1 | 1.0x |
| 2 | 1.5x |
| 3 | 2.0x |
| 4 | 2.5x |
| 5 | 3.0x |

不再使用当前“3 人后固定为 2.0x”的硬编码。最大计数应为配置项 `MaxCaptureContributors`；默认取当前编队能够部署的最大步系单位数，不能继续固定为 4。

双方同时存在有效占领者时保持“争夺中，进度暂停”。某方离开、死亡或收到新命令后，应在下一次战斗 Tick 中停止贡献。

### 3.3 鼠标点击决定编队正面

每次接受移动、攻击或占领命令时计算：

```text
DesiredFacing = TargetCell - CurrentAnchorCell
```

规则如下：

- 将方向量化为 8 个格子方向，保存在 `CommanderGroupRuntime.Facing`。
- 本次命令的所有目标槽位都围绕 `Facing` 旋转。
- 纵向阵型沿正面反方向向后排布。
- 横向阵型沿正面的垂直方向展开。
- 方形或默认行军布局也需要根据正面旋转槽位顺序。
- 单位沿路径移动时可以短暂朝向下一路径点，抵达最终槽位后必须统一朝向本次点击目标。
- 原地点击或方向长度为零时，保留上一次有效 `Facing`。

这里的“跟着鼠标”指命令发出时朝向鼠标点击的地图格，不要求部队在没有新命令时逐帧追踪鼠标悬停位置。

## 4. “排兵布阵”临时指令

### 4.1 指令入口

战斗 UI 中将当前“调整阵型”入口统一改名为“排兵布阵”。点击后：

- 只编辑当前激活指挥官编队。
- 只有编队处于 `Idle`、全员停止移动且没有交战时才能进入。
- 玩家可以使用纵向、横向、方形预设，也可以在 3×3 槽位中手动交换单位。
- 编辑期间只修改草稿，不立即修改正式槽位和单位位置。
- 点击确认后批量验证并执行一次重整移动。
- 点击取消、右键、切换指挥官时丢弃草稿。

### 4.2 临时有效期

确认排兵布阵后，编队获得一份临时布局：

```csharp
bool HasTemporaryFormation;
FormationLayoutSnapshot TemporaryLayout;
int TemporaryFormationSequence;
```

临时布局在以下期间有效：

- 排兵布阵重整过程中。
- 重整完成后的原地待命阶段。

以下任一玩家命令被成功接受时，临时布局立即失效：

- `Move`
- `AttackGroup`
- `CaptureBuilding`
- 新的 `Regroup` / “排兵布阵”指令替换旧草稿

命令校验失败时不得让临时阵型失效。例如点击不可达区域后移动命令被拒绝，当前排兵布阵结果仍保留。

### 4.3 阵型失效后的移动布局

“失效”不等于取消编队或让单位自由散开。移动命令成功后：

1. 清除临时自定义槽位快照。
2. 根据存活成员的稳定 `SpawnOrder` 生成默认行军槽位。
3. 使用本次点击产生的 `Facing` 旋转行军槽位。
4. 全部成员仍按同一条编队命令移动，其他指挥官编队不受影响。
5. 到达后保留默认行军布局，但 UI 不再显示为玩家已确认的“排兵布阵”状态。

建议新增布局状态：

```csharp
enum FormationPersistence
{
    DefaultMarching,
    TemporaryArranged
}
```

> 字段迁移：现有 `FormationLayoutSnapshot.Locked` 仅保留“部署阶段的初始布局”语义（开战状态始终有效）；战斗移动不再读取 `Locked` 快照，而是每次按 `Facing` 与 `SpawnOrder` 生成 `DefaultMarching` 槽位。`CommandRegroup` / `CommandCustomRegroup` 确认后写入 `TemporaryArranged`，不再 `Layout.Capture(..., locked: true)` 永久锁定。两套语义（部署初始布局 / 战斗临时阵型）不得混用。

不要通过清空 `CommanderGroupId`、逐个单位下令或关闭槽位预留来实现阵型失效。

## 5. 占领位置分配

### 5.1 两层位置区域

建筑附近的位置分为两层：

- `CaptureRing`：紧邻建筑占地边缘的第一圈，只优先分配步系占领单位。
- `SupportRing`：第一圈外的第二圈，分配非步系单位以及第一圈放不下的成员。

分配顺序：

1. 按距离、路径长度和与目标正面的关系稳定排序合法格。
2. 步系单位按 `FormationSlotIndex`、`SpawnOrder` 稳定分配 `CaptureRing`。
3. 非步系单位分配 `SupportRing`。
4. 如果 `CaptureRing` 尚有空位且支援格不足，允许非步系单位使用剩余外圈格，但不计入占领速度。
5. 步系单位多于 `CaptureRing` 可用格时，超出部分分配 `SupportRing`，不计入占领速度（有效贡献者上限 = min(步系单位数, 可用 CaptureRing 格数)）。
6. 任一成员无合法位置或无路径时，整条命令失败。

目标分配必须稳定，同一地图状态下重复点击同一建筑不应让成员随机交换位置。

### 5.2 建筑较大或靠近边界

- 根据实际建筑 `Footprint` 生成两层环，不假定建筑固定为 2×2。
- 过滤越界、不可行走、永久障碍和其他编队预留格。
- 建筑靠近地图边缘时允许只使用仍合法的一侧，但必须能容纳全队。
- 如果合法格总数不足，UI 显示“建筑周边空间不足”。

## 6. 命令状态与打断

建议将占领拆成明确阶段，而不是只用一个 `Capturing` 状态覆盖移动和读条：

```text
Idle
  -> MovingToCapture
  -> Capturing
  -> Idle
```

如果暂时不增加枚举，可在 `CaptureCommandRuntime` 中保存阶段：

```csharp
enum CaptureCommandPhase
{
    Approaching,
    Capturing
}
```

最低运行时数据：

```csharp
int CommandSequence;
int BuildingInstanceId;
Vector2Int ClickedCell;
Vector2Int DesiredFacing;
Dictionary<string, Vector2Int> AssignedCells;
HashSet<string> ContributorUnitIds;
CaptureCommandPhase Phase;
```

打断规则：

- 新移动、攻击、占领或排兵布阵命令：取消旧占领、清除贡献者状态、释放建筑周边预留。
- 步系单位死亡：下一 Tick 重新计算有效人数，不重新排列整个队伍。
- 建筑被友军提前占领：结束本编队占领命令并进入 `Idle`。
- 目标建筑失效：释放全部预留并报告“目标已失效”。
- 指挥官编队失败：立即取消占领，失败编队不得继续贡献进度。
- 站桩攻击（已在射程内，`moveIntoRange=false`）：视为一次成功接受的攻击命令，同样触发临时阵型失效。

## 7. 代码改造清单

### `Battle/Commanders/CommanderGroupRuntime.cs`

- 增加稳定的 `Facing`。
- 增加临时阵型是否有效及其命令序号。
- 增加或引用 `CaptureCommandRuntime`，避免只保存字符串形式的建筑 ID。

### `Battle/Commanders/CommanderGroupCommandController.cs`

- `CommandMove` 成功后使临时排兵布阵失效，并按目标方向生成默认行军槽位。
- `CommandAttack` 和 `CommandCaptureBuilding` 同样更新 `Facing` 并使临时阵型失效。
- 重写 `CommandCaptureBuilding`：收集全部存活成员，生成两层目标区域并一次性预留。
- 步系单位优先贴近建筑，非步系单位进入支援位。
- 到位判定从“部分占领者移动完成”改为按每个成员的分配位置检查。
- 占领完成后不再自动恢复旧锁定阵型。
- 重写移动到位检测：`AtLockedSlots` / `BuildLockedTargets` / `EnsureLockedLayout` 不再以锁定的 `group.Layout` 为准，改为按本次命令的 Facing + 默认行军槽位（或临时阵型）计算目标与完成判定；占领命令的到位检测按每个成员的分配格单独判断（CaptureRing / SupportRing），不复用 `AtLockedSlots`。
- `CommandRegroup` / `CommandCustomRegroup` 确认后写入 `TemporaryLayout`（`FormationPersistence.TemporaryArranged`），不再 `Layout.Capture(..., locked: true)` 永久锁定。
- `CommandCaptureBuilding` 增加失败原因 out 参数（无步系 / 建筑周边空间不足 / 目标不可达 / 目标已失效），供 UI 提示。
- `CommandAttack` 站桩攻击（已在射程内）同样触发临时阵型失效。

### `Battle/Buildings/BuildingCaptureController.cs`

- 只统计持有有效占领命令且已到指定占领格的步系单位。
- 通过 `UnitData.CommanderGroupId` 反查编队的 `CaptureCommandRuntime`，校验命令目标为本建筑、单位当前格等于其分配格后再计入；为每方建立“命令 → 贡献者”映射，替代当前全局 tag 扫描。
- 去掉固定 `MaxCounted = 4` 和 3 人封顶倍率。
- 使用可配置的贡献者上限、单人基础速度和每增加一人的增益。
- 保留双方争夺时暂停进度。
- 确认敌方占领路径：若 AI 不通过 `CommandCaptureBuilding` 下发命令，保留“无命令时按 tag + 紧邻格”回退，否则敌方将无法占领。

### `Battle/Buildings/BuildingRegistry.cs` 或建筑配置

- 增加占领参数配置入口，避免倍率继续硬编码在控制器中。
- 城市与兵工厂可以使用不同的基础占领时间，但使用同一人数加速规则。

### `Battle/Formation/FormationController.cs`

- 将战斗入口语义统一为“排兵布阵”。
- 确认后写入临时阵型，而不是永久锁定布局。
- 提供 `InvalidateTemporaryFormation(group, sequence)`。
- 预设和自定义槽位都根据 `Facing` 旋转。
- 切换指挥官时恢复各自草稿/临时布局显示，不污染其他编队。
- 明确 `FormationLayoutSnapshot.Locked` 仅表示“部署初始布局”，战斗移动不再读取；战斗阵型用 `FormationPersistence`（DefaultMarching / TemporaryArranged）区分。

### `Battle/UI/BattleUiController.cs`

- 按钮文字改为“排兵布阵”。
- 显示“布阵中 / 已布阵 / 行军阵型”状态。
- 移动命令成功后立即清除“已布阵”高亮。
- 占领失败时显示具体原因：`没有步系单位`、`建筑周边空间不足`、`目标不可达`、`目标已失效`。

### `Battle/Units/UnitMovementController.cs`

- 保留路径段朝向逻辑。
- 支持最终到达时应用命令保存的统一 `Facing`。
- 不允许单个单位自行决定编队最终朝向。

## 8. 与现有总规则的冲突与更新

当前《指挥官编队玩法完善规则》的第 6.3.2、10、12 节要求战斗移动长期保持锁定的阵型快照。新的“点击移动后排兵布阵失效”需求会改变这一约束。

正式实现前应同步修改总规则为：

- 部署阶段的初始布局仍作为开战初始状态。
- 战斗中的“排兵布阵”是临时布局。
- 下一条成功接受的移动、攻击或占领命令会使临时布局失效。
- 失效后回到面向命令目标的默认行军布局，而不是退回单兵自由控制。
- 命令失败不改变当前布局。
- `FormationLayoutSnapshot.Locked` 仅保留“部署初始布局”语义；战斗移动按 Facing 生成默认行军槽位，战斗重整写入临时阵型，两者由 `FormationPersistence` 区分。

完成规则更新后再修改代码，避免实现与项目强制规格互相矛盾。

## 9. 实施顺序

### 阶段 A：朝向数据与槽位旋转

- 增加 `Facing`。
- 命令入口统一计算目标方向。
- 让预设、默认行军和最终单位朝向使用同一方向。

验收：从编队八个方向点击地面，编队正面均朝向点击格，槽位不会仍固定在世界轴。

### 阶段 B：临时排兵布阵

- 改名并整理战斗 UI。
- 增加临时阵型状态。
- 只在命令成功后使临时阵型失效。
- 移动改用默认行军布局。

验收：确认自定义阵型后保持原地；点击合法移动目标后高亮消失并切换行军布局；点击非法目标后阵型仍保留。

### 阶段 C：整编队占领

- 建立两层建筑周边位置。
- 全部成员批量分配、校验、预留和移动。
- 步系单位进入占领圈，其他单位进入支援圈。

验收：点击建筑后只有当前指挥官全队移动，其他编队不动，且不存在成员留在原地或目标格重叠。

### 阶段 D：人数驱动占领速度

- 占领贡献绑定到有效命令和指定位置。
- 改为可配置人数倍率。
- 完成争夺、死亡、离开和打断处理。

验收：相同建筑由 1、2、3、4 名步系单位占领时耗时依次缩短；非步系单位不增加速度。

### 阶段 E：异常与回归

- 补充建筑边界、拥挤、不可达、目标失效和连续命令测试。
- 验证多指挥官编队隔离。
- 编译并在 Unity 场景中进行运行时验收。

## 10. 必测用例

1. 当前编队有 3 名步系与 2 名非步系单位，点击城市后 5 人全部移动；3 名步系优先贴近建筑，2 名非步系进入支援位。
2. 当前编队没有步系单位，点击建筑时命令被拒绝，全队不移动，并提示“没有步系单位”。
3. 建筑附近无法容纳全队时整条命令失败，不允许只有步系单位先走。
4. 1、2、3、4 名有效步系单位的占领时间逐级缩短。
5. 非步系单位即使站在紧邻外圈也不贡献占领速度。
6. 双方步系单位同时有效占领同一建筑时进度暂停。
7. 占领中下达移动命令，所有占领贡献立即取消，预留全部释放。
8. 从编队北、东北、东、东南、南、西南、西、西北八个方向点击，最终正面均朝向点击位置。
9. 单位绕障碍移动时可朝向路径，但抵达后全部恢复为命令目标朝向。
10. 完成排兵布阵后原地保持；成功移动后临时阵型失效并改用默认行军布局。
11. 移动命令因不可达被拒绝时，临时阵型不失效。
12. A 指挥官占领建筑时切换到 B 指挥官下令，不得改变 A、B 的成员归属或把命令发给错误编队。

## 11. 完成定义

- 点击建筑会驱动当前指挥官的全部存活成员靠近建筑。
- 步系单位数量真实、连续地影响占领速度，非步系单位不贡献。
- 全队的目标阵型正面由本次鼠标点击位置决定。
- “排兵布阵”是明确的临时指令，后续成功移动后失效。
- 阵型失效仍保持编队整体控制、稳定槽位分配和批量合法性验证。
- 多指挥官之间的命令、预留、朝向和 UI 状态保持隔离。
- 所有必测用例通过，C# 编译无错误，Unity 运行时无异常日志。
