## 第三个 Bug 修复 — "添加层级视角变了但第二层不出现"

**用户报告**：点"⬇ 添加层级"按钮 → 视角转变（相机移到新 Z 平面）→ 但 UI 按钮只剩"第1层"，没出现"第2层"。

### 真因（双重 bug）

**Bug 1（致命）：OnGUI 末尾的同步逻辑强制覆盖 `_maxZInData`**

```csharp
// OnGUI() 末尾（line 110-120）
if (_mapData != null) {
    int newMax = 0;
    for (int i = 0; i < _mapData.Tiles.Count; i++) // ← 0 个 tile → newMax=0
        if (_mapData.Tiles[i].Z > newMax) newMax = _mapData.Tiles[i].Z;
    if (newMax != _maxZInData) {                    // 0 != 1 → 强行覆盖
        _maxZInData = newMax;                       // ← 把用户刚设的 1 改回 0
        if (_activeZ > _maxZInData) _activeZ = _maxZInData;  // _activeZ 也被夹回 0
    }
}
```

**Bug 2（次要）：闪烁代码 `Repaint()` 不能触发 SceneView 重绘**

```csharp
if (_levelAddTime > 0) {
    ...
    Handles.DrawWireCube(...);
    Repaint();  // ← EditorWindow.Repaint()，不是 SceneView.Repaint()，Scene 视图不会持续重绘
}
```

`Repaint()`（不指定对象）重绘的是当前 EditorWindow（即 HandMapBuilderWindow），不会触发 SceneView 重绘。所以闪烁 wire cube 实际只画了一帧。

### 修复（`HandMapBuilderWindow.cs`）

1. **新增** `int _userReservedMaxZ` 字段 — 记录用户主动保留的层级
2. **OnGUI 末尾同步逻辑** 改为 `newMax = Mathf.Max(newMax, _userReservedMaxZ)`，只增不减
3. **AddLevel / + 快捷键 / RemoveHighestZ / ClearLevel / ClearAllLevels / CreateNewAsset / 新场景** 全部同步维护 `_userReservedMaxZ`
4. **闪烁代码** 把 `Repaint()` 改成 `SceneView.lastActiveSceneView.Repaint()` —— Scene 持续重绘
5. **闪烁 box 位置** 从 `_maxZInData` 改成 `_activeZ`（更准确画在新加的那层）
6. **AddLevel** 加 `Debug.Log` 方便排查

### 教训

- 任何"OnGUI 末尾同步状态"逻辑，**只增不减**是更安全的策略——用户主动设置的状态不应被"数据扫描"覆盖
- SceneView 内的动画必须用 `SceneView.Repaint()` 才能持续刷新
- Repaint() 默认是当前 EditorWindow，不能跨窗口触发重绘
- **别在 `FocusSceneViewOnLevel` 里强制设置用户的相机 size/rotation/orthographic** —— 会破坏用户已配置的视角
- **鼠标事件里没过滤 Alt 修饰** → Alt+右键（zoom）、Alt+左键松开等 SceneView 相机操作会被吞掉
- 用户报"鼠标没法移动"通常是相机被强制改到一个很远的 size + 奇怪的 rotation，看起来地图很小、鼠标像没响应

## 阶段 5 修复（索引失效 + 粘贴越界）

### 用户反馈
用户 Console 异常刷屏：
- `ArgumentOutOfRangeException: Index was out of range` at `HandMapBuilderWindow.cs:1488` (TryGetSelectionRect)
- 调用栈：`OnSceneGui → DrawBoxSelectionVisual → TryGetSelectionRect`
- 日志时序：复制 170 → 粘贴（落点 110,36 超出 50×50 → 全部越界 → "放置 0 个"）→ 清空所有层级（20013 个）→ 后续每次 SceneView 重绘都抛

### 真因

- `_selectedTileIndices` 存的是 tile 索引，但 `ClearLevel / ClearAllLevels / RemoveHighestZ / ApplyGridSize` 把 tile 删掉后**索引就失效了**，下次 SceneView 重绘访问 `_mapData.Tiles[idx]` 抛 ArgumentOutOfRangeException
- 一旦异常抛一次，IMGUI 内部 Group/Clip 栈被破坏 → 后续每次绘制都报 "GUI Error: You are pushing more GUIClips than you are popping"
- 复制组超出地图边界时，paste 时把所有 170 个都"越界裁掉"→ "放置 0 个"，UX 不友好

### 修复（`HandMapBuilderWindow.cs`）

1. **统一方法 `InvalidateSelectionReferences()`** — 清空 `_selectedTileIndices` + `_clipboard` + 状态回 Idle
2. **`ClearLevel` / `ClearAllLevels` / `RemoveHighestZ` / `ApplyGridSize` 缩窄后** 全部调用 `InvalidateSelectionReferences`
3. **`TryGetSelectionRect` 防御性索引检查** — 倒序遍历同时剔除失效索引
4. **`DrawBoxSelectionVisual` 已选 tile 高亮循环** 同样防御
5. **`PasteAtCurrentHover` 完全越界拦截** — 复制组完全超出地图时不再生成"放置 0 个"的刷屏日志
6. **`DrawPasteGhostPreview` Ghost 标签显示 "X/Y ⚠越界 Z"** — 让用户清楚能看到越界几个、贴几个

### 教训

- **任何 `List<int>` 存储数据集合的索引都必须考虑：数据集合可能在你不知情时被外部变更**（用户点清空、缩窄地图、撤销）
- 防御方案：①每次访问前验证 idx 范围并清理；②重大变更后统一清理
- 一旦 IMGUI 异常，**GUI clip 错误会作为副作用持续刷屏**——主异常修了它就停
- 任何"自动剪裁"操作要给用户**可见提示**（不是 silent skip）

## 用户反馈第六轮 bug — "Stairs_1 旋转后边对不齐格子"

### 症状
user 选中旋转 90°/180° 后，视觉上 staircase 偏离格子中心，**与旁边方格"留缝"或"出框"**。

### 真因（多因叠加）

1. **Mesh 几何中心 ≠ (0,0,0)** —— 大多数 IsoPack prefab（Stairs_1/Bridge1/Stairs_2 等）的 mesh 几何中心 (bounds.center) 偏离 prefab root 原点。当用户旋转 90°/180° 后，绕 (0,0,0) 旋转——几何中心就漂到格子另一角，视觉上"飘"。
2. **`Vector3.one * 0.5f` 硬编码 scale** —— 数据层有 `HandAuthoredMapData.DefaultPrefabScale` 字段，但编辑器硬编码忽略它，用户在 Inspector 调了也没用。
3. **`DestroyImmediate(goOld)` vs `Undo.DestroyObjectImmediate(goOld)`** —— 在某些 EnsurePreviewFor 路径下还在用裸 DestroyImmediate，与同函数的 Undo.RegisterCreatedObjectUndo 不对称。

### 修复方案：自动 pivot 修正 + 可选手动偏移

#### Part 1：自动几何中心对齐（解 root cause）
新增 `static void AlignPrefabGeometryToCellCenter(GameObject instance)`：
- 读 `instance.GetComponentInChildren<MeshFilter>().sharedMesh.bounds.center`
- 用 `instance.transform.TransformVector(b.center)` 算 mesh 几何中心相对 instance.position 的世界空间偏移（考虑旋转+scale）
- `instance.transform.position -= offset` 把几何中心挪到格子中心

调用点：`EnsurePreviewFor` 在设置 rotation/scale 后、_spawnedByCell[key] = instance 之前调用。

#### Part 2：数据层加 OffsetX/OffsetY 字段
`HandPlacedTile` 加 `float OffsetX / OffsetY`：
- 默认 0（struct 字段默认）
- 旧 .asset 反序列化无字段时也默认 0
- 坐标系：OffsetX = 世界 X，OffsetY = 世界 Z（对应 GridToWorld 把网格 y 映射到世界 z）

`EnsurePreviewFor` 读取 `t.OffsetX/t.OffsetY`，在自动 pivot 修正**之后**再叠一层手动偏移：
- 默认 0 → 啥也不动
- 用户在 Inspector 拉到某个值 → 视觉往 X/Z 方向挪 0~1 格

#### Part 3：Inspector 加 X / Y 偏移滑条
在 DrawTileInspector 已选中段，height slider 下方加：
```
水平偏移 (手动微调)
X: [-1, +1]
Y: [-1, +1]
```
GUIContent tooltip 解释"自动 pivot 已保证几何中心，滑条是额外微调"。

实时写回数据 + 实时挪 instance.position（不走 RebuildAllPreviews，避免触发整层重建刷新）。

### 数据层读取联动
`EnsurePreviewFor`：`float scale = _mapData != null ? _mapData.DefaultPrefabScale : 0.5f;` —— 终于让用户能从 HandMap Inspector 改 `DefaultPrefabScale` 字段生效。

### 关键修改文件

- `Assets/Editor/HandMapBuilder/HandMapBuilderWindow.cs`
  - `EnsurePreviewFor` 重写：~30 行（读 DefaultPrefabScale + OffsetX/Y + AlignPrefabGeometryToCellCenter 调用）
  - `AlignPrefabGeometryToCellCenter`：~14 行静态方法
  - `DrawTileInspector`：~30 行新增 X/Y 偏移滑条
- `Assets/Scripts/Battle/Map/Generation/HandAuthoredMapData.cs`
  - `HandPlacedTile` 加 `OffsetX/OffsetY` 两个 float 字段

### 教训

- **Pivot 不是原点**：3D prefab 经常 `bounds.center != (0,0,0)`，旋转后会"飘"。Editor 工具链要把 mesh 几何中心对齐到格子中心，而不是依赖 prefab 原点。
- **`TransformVector` vs `TransformPoint`**：算 mesh 偏移用 `TransformVector` 而不是 `TransformPoint`——后者包含 translation，前者只跟随 rotation+scale。
- **数据字段埋着没用**：data layer 加了 `DefaultPrefabScale` 字段，editor layer 写死了——字段等于不存在。Editor 读取数据 layer 的字段是基本契约。
- **自动 + 手动两层机制**：自动解决 root cause（90% 情况不需操作），手动留个口子给创作需求（10% 情况需要微调）。比"全自动但失控"或"全手动但繁琐"都好用。
- **GUI 不展示 = 用户不知有这功能**：OffsetX/OffsetY 不在 Inspector 露出 → user 永远不知道。给数据层加字段一定要在 Editor UI 加对应控件。

### 后续边界 case 修补（同一轮）
1. **HeightOffset Inspector 滑块原本用 `transform.position = new Vector3(w.x, w.y+hOff, w.z)`** —— X/Z 直接覆盖导致丢失:
   - `AlignPrefabGeometryToCellCenter` 算过的几何中心补偿（这个不依赖于 height，但在 SelectTile 后 instance 已被 pivot 修正过）
   - 用户的 `OffsetX/OffsetY`（这个本来就依赖，但 height 滑块 block 完全没读它）
   - **修复**：height 滑块和 offset 滑块统一改 `Undo.DestroyObjectImmediate(go) → EnsurePreviewFor(key, prefab, registerUndo: false)` 重建，让 pivot 修正 + Offset 两层叠加永远一致。
2. **`RelayoutAllPreviews`（layerHeightScale 改变时调用）原本只重置 Y 坐标**：X/Z 保留 → 几何中心补偿不会丢。但**没读 OffsetX/OffsetY** → 用户手动偏移在改 layerHeightScale 时被清。
   - **修复**：循环里加 `offX = t.OffsetX; offY = t.OffsetY;`，重新定位时 `Vector3(w.x + offX, w.y + ho, w.z + offY)`。
3. **滑条重建路径性能隐患**：用户拖动 Inspector 滑块连续触发,Unity OnGUI 在拖动时可能 60 fps 调用。重建 instance 触发 `EnsurePreviewFor` 是 producer 侧 ~100 行 GC alloc。可接受,因为:①只在 Inspector 滑条活动时;②单格 tile 重建而非全图;③ user 仅在精调时才会触发。如果将来要优化,可以加 `Event.current.type == MouseUp` throttle。

## 第七轮回退 — "你改了什么，我怎么看不到地形了"

**教训极其严重**——一顿"看似合理"的优化导致 user 完全看不到地形。立刻回退。

### User 反馈（直接原话）
- "你改了什么，我怎么看不到地形了，给我回退，只做一个水平偏移 (手动微调) X: / Y: 就可以了"

### 真因
本轮所做的 5 件事中，4 件是回退原因：

1. **`AlignPrefabGeometryToCellCenter` 自动 pivot 修正**：调用 `instance.transform.TransformVector(b.center)` 然后 `position -=`。Pivot 修正**计算错了**：对某些 prefab 来说 geometry center 偏移就是 1~2 单位，反向挪动后整个 instance 移出视野 → **地形跑出 Scene 视图看不到**。
2. **`Vector3.one * scale`（其中 scale = DefaultPrefabScale）**：默认 0.5，但**新建的 prefab 没设置 DefaultPrefabScale 字段**，OnEnable 中读到的是 0（旧资产反序列化），导致 `localScale = 0` → mesh 完全缩没 → **整个 tile 看不见**。
3. **Collider 清理改 `Undo.DestroyObjectImmediate`**：连带改动，没单独坏处但是污染了 diff 范围。
4. **Height 滑块改重建路径**：性能影响 + 失去"实时调整"的快速反馈。

### 保留的正确改动
1. **数据层 `HandPlacedTile` 加 `OffsetX/OffsetY`** ✓ 保留
2. **Inspector 加 X/Y 偏移滑条** ✓ 保留
3. **`EnsurePreviewFor` 读取 OffsetX/Y 并叠加到 world.x/world.z** ✓ 保留
4. **`RelayoutAllPreviews` 读取 OffsetX/Y 以保留 layerHeightScale 变更时的手动偏移** ✓ 保留

### 撤回（已执行）
1. 删除 `AlignPrefabGeometryToCellCenter` 方法及其在 `EnsurePreviewFor` 里的调用
2. `EnsurePreviewFor` 的 `scale = _mapData.DefaultPrefabScale` 改回硬编码 `Vector3.one * 0.5f`
3. `EnsurePreviewFor` 的 `DestroyImmediate(existing)` / `DestroyImmediate(cols[i])` 保持原状（不换 Undo）
4. Height 滑块从"重建 instance"改回"直接 SetPosition"
5. X/Y 滑块从"重建 instance"改回"直接 SetPosition"
6. 删除 `HandMapPrefabBoundsDiagnostic.cs` 和 `.meta`（新增的诊断脚本，不在 user 要求内）
7. `HandAuthoredMapData.cs` 注释里"配合自动对齐几何中心"那一句改成"让用户让 tile 偏离格子中心"

### 教训（最重要）
- **用户看不到东西 = P0 灾难**。无论原本想做得多优雅，"破坏可见性"的改动一律不许上车。
- **"自动 pivot 修正"看似漂亮但极易写错**：`bounds.center` 在 prefab 嵌套结构和 root scale ≠ 1 时计算复杂，"对齐到几何中心"的算法没有测试覆盖的资产就别上。
- **`OnEnable` + 默认值 0** 是隐形坑：旧 .asset 反序列化没字段 → 默认 0 → localScale 0 → 整 tile 不可见。**任何 multiply-by-field 的代码都要做"读到 0 当作 1"或"读到 0 跳过"的兜底**。
- **收到 user "看不到"的反馈时，立刻回退而非继续调研**：可视化破坏先恢复再说，再去 debug 任何"看起来不错的优化"。
- **改进是累积动作**：一次只加 user 明说要的功能，不要附带 bonus 改动。每一行新代码 = 新的失败面。
- **增量改动原则**：先写最少的 user 明确要的功能 → 让 user 验证 → 再问"还想加什么"。中间绕弯的"我觉得你也应该要"是噪音。

## 用户反馈第八轮 UX bug — "选中后拖动 = 框选" + "Z>=1 鼠标定位偏移"

### 症状（User 原话）
- "我选中地形的时候拖动鼠标，怎么是框选啊，我按esc应该是不选择任何地形，然后才可以框选，要不然就是地形放置模式"
- "第二层级的时候，鼠标定位地形框也定位不准，你修复一下吧"

### Bug 1：选中 tile 后拖动会触发框选（user 期望：选中后进入 Inspector 编辑模式，Esc 才退回 Idle）

**真因**：`enum BuilderState` 只有 4 个值（Idle/BoxSelecting/BoxSelected/ReadyToCopy），**没有"选中后等待编辑"状态**。`PickTileAtHover` 调用后只设了 `_selectedTileForEdit` 但**状态仍为 Idle**，下一次左键按就回到原本的 PlaceAt/框选路径。

**修复**：
1. `enum BuilderState` 加第 5 个值 `InspectingTile`（Shift+左键 选中已放置 tile 后进入；Esc 退回 Idle）
2. `PickTileAtHover` 选中成功后 `_state = BuilderState.InspectingTile`
3. `HandleSceneEvents` MouseDown/MouseDrag/MouseUp 三段加 InspectingTile 状态守卫，return 出去不响应画/框选
4. Inspector 区"清除选中"按钮、`Esc` 快捷键、`DrawBoxSelectionControls` 状态显示都同步 InspectingTile → Idle 的退出路径
5. 用户原话期望："我按esc应该是不选择任何地形，然后才可以框选，要不然就是地形放置模式" → 完全契合：选中后 → 按 Esc → 回 Idle → 此时左键拖动才进框选/画路径

### Bug 2：Z>=1 时鼠标定位地形框偏移

**真因**：`MouseToWorld(Vector2 mousePos, int z)` 把 plane point 设为 `(0, -z, 0)`。但 Unity `Plane(normal, point)` 的语义是 `normal·X + dot(normal, point) = 0`，等价于"plane = 点积为 -dot(normal, point) 的面"。我们其实要的是 "y = z*scale" 平面 → plane point 应该是 `(0, z*scale, 0)`（不是 -z）。

**计算验证**：
- `GridToWorld(0, 0, z) = (0, z*scale, 0)` —— tile Z=z 平面在 y = z*scale
- 旧代码 plane y = -z（=_layerHeightScale=1 时）→ 鼠标射线打 y=-1 平面而非 y=+1 平面，Z>=1 时偏移 2 单位
- 新代码 plane y = z*scale → 与 tile 渲染位置对齐

**修复**：`new Plane(Vector3.up, new Vector3(0, z * _layerHeightScale, 0))`

### 关键修改文件
`Assets/Editor/HandMapBuilder/HandMapBuilderWindow.cs`:
- `BuilderState` enum 加 `InspectingTile`（line 60）
- `PickTileAtHover` 设 `_state = InspectingTile`（line 2623）
- DrawTileInspector "清除选中" 按钮 重置状态（line 950-955）
- Esc 快捷键段加 InspectingTile → Idle 分支（line 1162 起）
- DrawBoxSelectionControls 状态显示加 InspectingTile 分支（line 617-622）
- HandleSceneEvents MouseDown/MouseDrag/MouseUp 各自加 InspectingTile 守卫（line 1509-1599）
- MouseToWorld plane point 修复（line 2506-2520）

### 教训

- **状态机要覆盖 user 期望的所有模式**：user 说 "选中 tile 后跟 Idle 不一样" 时，状态机里就必须有"选中后待编辑"这个状态。Idle 是个万能状态 = "啥也没发生"，但 UX 上 user 操作完一件事后常需要"等下一步动作"。
- **Unity Plane 构造签名容易写反**：`Plane(normal, point)` 的 point 是"平面上一点"，不是"距原点的带符号距离"。unity doc 字符串"a given normal" + distance 算实际公式是 `n·p + d = 0`，等价 `d = -n·p₀`。所以 plane y = h 是 `Plane(up, (0, h, 0))` 而不是 `(0, -h, 0)`。我两次写反了 (`-z`, 然后改成了 `-z*scale`)——最终才对。
- **状态机 bug 的形态常是 "user 期望有 N+1 个状态但代码只有 N"**：发现 user 路径不对时，先查 `enum`，看是不是漏了状态。
- **回报用户期望的语义而不是生硬说 "我修了"**：user 原话用 "我按esc 应该 X 然后 Y" 给了我具体 UX flow，重构时直接对齐即可。

## 第十一轮 UX 修正 — Esc/Enter/Space/Delete 在 SceneView 焦点下失效

此时按 Esc → SceneView 内部消化,Event 不会传到 EditorWindow 的 OnGUI,**键盘快捷键完全失效**。

### 修复 (`HandMapBuilderWindow.cs` `HandleSceneEvents` 末尾)

在 `HandleSceneEvents` 末尾加 KeyDown 处理分支(line 1645+),覆盖 Esc/Enter/Space/Delete 四键:

```csharp
if (e.type == EventType.KeyDown && !e.alt)
{
    if (e.keyCode == KeyCode.Escape) { 
        // 分流 ReadyToCopy / BoxSelected,BoxSelecting / InspectingTile
    }
    else if (e.keyCode == KeyCode.Return || ...) {
        // Enter 仅在 BoxSelected + 有选区时进入 ReadyToCopy
    }
    else if (e.keyCode == KeyCode.Space) {
        // Space 仅在 ReadyToCopy 时实贴
    }
    else if (e.keyCode == KeyCode.Delete || ...) {
        // Delete 在 BoxSelected / ReadyToCopy 且有选区时删选区
    }
}
```

`OnSceneGUI` 里的 `e.Use()` 有效,可正确消费事件。

### 教训(非常重要,后续碰到快捷键都要做这个检查)

- **EditorWindow 的 OnGUI KeyDown 处理只在窗口有焦点时触发**。用户只要跟 SceneView 交互过,焦点就在 SceneView,**所有 OnGUI 里的快捷键都会被冻结**。
- **快捷键必须在 OnSceneGUI 也注册一遍**(SceneView.duringSceneGui 回调就是 OnSceneGUI)。
- **`OnSceneGui` 里 `e.Use()` 能正确消费事件**,Unity IMGUI 事件流对 OnSceneGUI 同等对待。
- **任何键盘快捷键(包括 R/E/H/B/F 等绘图快捷键)都应该双路径注册**。这次我只补了 Esc/Enter/Space/Delete 四个 Esc 类键,**R/E/H/B/F 这类绘图快捷键暂时未补**——下次 user 反映"按 R 旋转没反应"再用同样模式补。
