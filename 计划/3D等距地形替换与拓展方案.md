# 3D 等距地形替换与拓展方案（Isometric Pack 3d v1.2）

## 1. 结论

**可以完全替换，且渲染管线兼容**。但资源包是单一生态度（草地）风格，现有 10 种地形类型中有 3 种（雪山、沙漠、道路）没有现成资产，需要用材质变色/混合方案补全。替换的本质是**地形视觉层从 2D SpriteRenderer 架构切换到 3D Mesh 架构**，逻辑层（网格、寻路、部署、战斗）不动。

用户已确认的方向：完全替换 + 动手前先导入 Demo 场景确认观感。

## 2. 资源包调研结论（硬数据）

资源包：`C:/Users/PC/Desktop/Isometric Pack 3d v1.2/Isometric Pack 3d v1.2.unitypackage`（247MB，968 个资产，Unity 2017.4 / prefab 为 5.2 二进制格式，导入现代 Unity 会自动升级）。

| 检查项 | 结论 |
| --- | --- |
| Shader 兼容性 | ✅ 全部 `MK4Toon*` 系列为 `#pragma surface surf Standard` 的 **Built-in surface shader**，与本项目 Built-in 管线同源，不会变粉（与之前 Portal Effect URP 包本质不同） |
| Tile 实际尺寸 | 解析 FBX 顶点实测：**200×200cm 网格设计**（FBX 以厘米为单位）。按 Unity 默认导入（File Scale 0.01）≈ **2×2 世界单位**。当前游戏格子是 1 单位，需 0.5 缩放对齐（或实测后免缩放，见阶段 0 验证项） |
| Tile 变体体系 | `Tile_1_A..H` / `Tile_1_brick_A..H` / `TileMob_1..4` 各带 A–H 八个边缘变体 → 支持地块拼接过渡（对应现有道路 mask 连接逻辑的 3D 版） |
| 植被 | 树 4 系列 30+ 款（其中 Tree3 带 `_aut` 秋季黄色变体）、植物 25 款、蘑菇 8 款 |
| 岩石 | Rock_01..11 共 11 款 |
| 水 | Tile_Water1A–D、Tile_Water2、Water1、瀑布 2 款（水面 Y=0、水深 6 单位） |
| 桥/坡/梯 | Bridge1/2、Tile_Ramp 8 款、Stairs 5 款 |
| **缺失地形** | ❌ **无雪山、无沙漠/沙地、无道路**专用地块 |

## 3. 现状架构 vs 目标架构

| | 现在（2D） | 目标（3D） |
| --- | --- | --- |
| 视觉载体 | PNG Sprite + `SpriteRenderer` | FBX Mesh + prefab 实例化 |
| 朝向 | 每格旋转对齐相机（`BattleCellView.Setup` 里的 hack） | 不需要，等距相机直接看 XZ 平面网格 |
| 遮挡/排序 | 手动 `sortingOrder = (x+y)*2+1` | Z-buffer 自动处理（不透明几何） |
| 地形高度 | `TerrainCatalog.GetElevation`（0.04/0.08/0.12 抬 Sprite） | 真实几何高度（阶段 1 先不用，仅作视觉） |
| 逻辑层 | cell(x,z) → 世界(x,0,z)，射线拾取/寻路不读视觉 | **不变** |

需改造的核心文件（仅视觉层）：
- `TerrainVisualCatalog.cs`：Sprite 路径表 → 3D tile prefab 映射表（`Resources.Load<GameObject>`）
- `BattleCellView.cs`：新增 3D 分支（实例化 tile prefab、0.5 缩放对齐格子），保留现有 2D 分支作为 fallback，任何 prefab 加载失败自动退回当前贴图方案（和传送门一样的降级策略，保证场景永远能进）
- `BattleGridController.cs` / `UnitView.cs`：**不动**（单位仍在 y=0 平面）

## 4. 十种地形类型映射表

| TerrainType | 资源方案 | 备注 |
| --- | --- | --- |
| Plain | `Tile_Grass1..5` 随机 / `Tile_1_A..H` 边缘变体 | 直接可用 |
| Forest | 草地 tile + `Tree1/2/4` 系列任一款 | 单格一棵，占格逻辑不变 |
| Hill | 草地 tile + `Rock_0x` 或 `Plants` 丛 | 阶段 1 视觉近似；阶段 3 可上真实高度 |
| Mountain | `Rock_01..11` 大石组合（1 格 1–3 块） | 不可达格，纯视觉 |
| SnowMountain | Rock + **白色 tint 材质变体** | 材质补全（见下） |
| Desert | 草地 tile + **沙色 tint 材质变体** + `Tree3_aut`（秋黄树）点缀 | 材质补全（见下） |
| ShallowWater | `Tile_Water1A..D` | 水面自带着色器动画 |
| Ocean | `Tile_Water2` / Water1 + 下沉放置 | 深水不可达 |
| Road | `Tile_1_brick_A..H`（砖石纹理天然像路） | 用现有 mask 连接逻辑选 A–H 变体 |
| Bridge | `Bridge1` / `Bridge2` | 横向按 mask 旋转 90° |

**材质补全方案（雪山/沙漠）**：MK4Toon shader 有颜色 tint 属性；对草地/岩石的纹理做色调重映射生成 `Snow`/`Sand` 材质变体（白化/黄化），成本低且风格统一。若 tint 效果不理想，备选方案是对纹理做离线换色后出独立贴图。

## 5. 分阶段实施

### 阶段 0：导入 + Demo 观感确认（用户要求的前置步骤）

1. 用户在 Unity 中导入 unitypackage（247MB，建议一次性全导，Mobile Assets 和 Demo 也导，后续阶段用得上）。
2. 打开 `Assets/Isometric Pack 3d/Demo/` 下的 `Scene_simple`（或 Scene1）跑一遍，确认这个 3D 卡通等距风格符合预期。
3. **验证项**：在场景里摆两块相邻 `Tile_Grass1`，确认无缝拼接的间距（验证 tile 是 1 还是 2 世界单位，决定后续缩放系数）；确认 MK4Toon 材质在本项目光照下不发粉。
4. 观感确认通过后才进入阶段 1；不通过则止损，零代码改动。

### 阶段 1：地形渲染层 3D 化（核心改造）

1. 从包里挑选并复制所需 tile/prefab 到 `Assets/Resources/Battle/Terrain3D/`（只挑，不搬全包，控制体积）。
2. `TerrainVisualCatalog` 增加 `GetTilePrefab(TerrainType)`：prefab 映射 + 缓存 + 坐标缩放系数。
3. `BattleCellView.Setup` 增加 3D 分支：prefab 非空 → 实例化为格子子物体、按验证过的系数缩放对齐；prefab 缺失 → 走现有 2D Sprite 分支（双保险）。
4. 移除 3D 分支里的相机旋转 hack 和 sortingOrder 依赖（保留在 2D fallback 分支）。
5. 验证：测试地图 + 随机地图各跑一次，检查拾取/移动/攻击射线不被 3D mesh 挡偏（射线应继续打逻辑层，必要时 tile mesh 设为忽略射线层）。

### 阶段 2：地形类型补全

1. 制作 Snow / Sand 材质变体并接入 `SnowMountain` / `Desert`。
2. Road 用 `Tile_1_brick_A..H` 按现有 mask 逻辑替换 `GetConnectedSprite` 的 3D 等价物。
3. Bridge 接入 `Bridge1` 并按 mask 旋转。
4. 验证：8+2 种地形全部有 3D 表现，随机地图生成结果与之前逻辑一致（`ComputeHash` 不变）。

### 阶段 3：拓展（替换完成后的增强项，按需推进）

- 地图边缘装饰（树/岩石围边）、水岸瀑布、`Sky` 天空盒、`Banner` 营地旗帜等 Props 点缀。
- 真实地形高度（Tile_Ramp / Stairs + 单位贴地对齐）——影响寻路与 `UnitView.AlignModelBottomToGround`，作为独立玩法特性单独立项。
- 大地图性能优化：Mobile Assets 低模版 / GPU instancing / 静态合批。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Tile 导入缩放与预期不符（1 vs 2 单位） | 阶段 0 实测后把系数写进 `TerrainVisualCatalog` 常量，一处改全局生效 |
| 3D mesh 拦截鼠标射线，拾取偏移 | tile 放独立 Layer 并从射线掩码排除，或射线全部走逻辑层接口 |
| 单位血条/选择框被 3D 地形遮挡 | 血条 Canvas 保持高 sortingOrder；实机确认 |
| 单一风格与现有军事卡通单位（Simple Military）混搭违和 | 阶段 0 Demo 里同时摆一个士兵模型对照确认 |
| 老版本 prefab（5.2 二进制）导入报错/丢失引用 | Unity 会自动升级；若报错则从 Mobile Assets 同名低模版替代 |
| 性能（40×40=1600 tile 实例） | 桌面端 30 万顶点量级可承受；不够再切 Mobile 版 + 合批 |

## 7. 明确不改动的内容

- `TerrainType` / `TerrainCatalog` 的通行、颜色、海拔逻辑规则
- `BattleGridController` 网格与坐标约定 cell(x,z)→(x,0,z)
- 随机地图生成、寻路、部署、编队、战斗、传送门撤离全部逻辑
- 现有 2D 地形 PNG 与代码路径（保留为 fallback，不删除）

## 8. 验收标准

- Demo 场景观感由用户确认通过（阶段 0 门禁）。
- 10 种地形全部有 3D 视觉，无粉色材质、无黑块。
- 点击、移动、攻击、部署的格子判定与替换前完全一致。
- 随机地图生成结果（哈希）与替换前一致。
- 任意 tile prefab 加载失败时自动退回 2D 贴图，战斗仍可正常进行。
