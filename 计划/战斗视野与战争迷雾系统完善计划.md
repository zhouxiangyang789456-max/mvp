# 战斗视野与战争迷雾系统完善计划

## 1. 目标与边界

在现有编队视野基础上，建立一套同时服务玩家表现、点击命令、敌方 AI、隐蔽技能和后续侦查玩法的统一视野系统。

MVP 目标：

- 地图格子具有 `Unexplored / Explored / Visible` 三态。
- 玩家所有存活指挥官编队共享队伍视野。
- 敌方单位、指挥官地图头像、血条和目标反馈只在当前可见时显示。
- 不可见敌人不得被点选或成为新的攻击目标。
- 敌方 AI 使用同一套视野判定，保留现有“最后已知位置”记忆。
- 隐蔽、嘲讽强制暴露和近距离破隐继续工作。

不在 MVP 内：视锥朝向、烟雾动态遮挡、高低差精确射线、声音侦测、战争迷雾存档、小地图。

## 2. 现有基础与差距

已有能力：

- `BattleVisionService` 会按慢 Tick 分摊刷新编队，合并成员 `VisionRange`，输出编队间可见关系。
- `BattleSpatialIndex` 使用格子桶查询附近敌人，避免全场单位两两遍历。
- `EnemyGroupAiController` 已根据可见目标决策，且有最后已知位置与记忆过期。
- `ConcealmentService` 和嘲讽技能已接入隐蔽、强制暴露与遗忘。

主要差距：

- 目前只有“观察编队 -> 目标编队”布尔关系，没有玩家团队共享的格子视野快照。
- 范围判定是纯圆形距离，森林、山地、建筑与高度尚不遮挡视线。
- 敌方模型、头像、血条与点击注册表未被视野快照统一驱动。
- `UnitSelectionController` 只拦截了隐蔽目标，普通的视野外敌人仍可被攻击。
- 没有未探索/已探索的地图视觉层。

## 3. 核心设计

### 3.1 视野层次

系统分为三层，但使用同一份快照作为事实来源：

1. `VisionGridState`：每个队伍的当前可见格、已探索格和版本号。
2. `GroupVisibility`：某编队是否被某队伍可见，由“至少一个存活成员所在格可见”得出。
3. `PresentationVisibility`：依据玩家队伍快照控制敌军模型、头像、血条、地面迷雾与点击命中。

玩家存活编队的视野做并集，不只显示当前激活指挥官的视野。激活编队仅决定控制与 UI 上下文，不影响团队情报共享。

### 3.2 三态语义

| 状态 | 地形 | 敌军 | 建筑/目标 |
| --- | --- | --- | --- |
| `Unexplored` | 高强度遮罩，只保留边界轮廓 | 隐藏 | 隐藏未发现目标 |
| `Explored` | 暗化但保留历史地形 | 隐藏，MVP 不显示敌人残影 | 显示已发现的静态建筑，不实时刷新敌方状态 |
| `Visible` | 正常 | 显示且允许点选 | 显示实时状态 |

己方单位、己方指挥官头像和必需的战斗 HUD 始终可见。

### 3.3 MVP 遮挡规则

第一版采用确定性格子视线，不使用物理射线：

- 指定格中心之间用 supercover line/Bresenham 遍历穿过的格子。
- `Mountain` 和 `SnowMountain` 阻挡后方视线；阻挡格自身可见。
- 建筑占地默认阻挡后方视线，通过建筑定义字段配置，不由模型高度猜测。
- `Forest` 在 MVP 中不完全阻挡，而是将穿越后的有效剩余视距减 2；方便之后替换为通用 `VisionCost`。
- 观察者所在格、目标格和与观察者相邻的格始终可见，避免近身盲区。

所有阻挡参数应放入 `VisionConfig`/ScriptableObject，不散落在 AI、地图或视觉脚本中。

### 3.4 更新时机

- 单位跨格、生成、死亡、提取、阵营变更、建筑生成/销毁和隐蔽状态改变时标记视野脏。
- 慢 Tick 合并脏区并分摊重算，但玩家点击前如快照过期，对当前涉及的编队做一次即时校验。
- 快照只在内容真正变化时递增版本号并发事件，避免每次刷新都让 UI/AI 无效刷新。

## 4. 系统改造清单

### `Battle/Vision/BattleVisionService.cs`

- 保留现有 API，内部拆分为“格子快照计算”和“编队可见关系派生”。
- 新增 `IsCellVisible(team, cell)`、`IsCellExplored(team, cell)`、`IsUnitVisible(team, unit)` 和 `VisionChanged`。
- 强制暴露只改变目标编队的可见性，不把目标周边地图一并点亮。

### `Battle/Vision/VisionGridSnapshot.cs`（新增）

- 使用固定尺寸 `BitArray`/位集保存 `Visible` 与 `Explored`。
- 保存队伍、地图尺寸、版本号和变化格列表，供视觉层做增量刷新。

### `Battle/Vision/GridLineOfSight.cs`（新增）

- 纯 C# 确定性算法，不依赖 `MonoBehaviour`、物理层或渲染对象。
- 输入观察格、目标格与 `IVisionBlockerProvider`，便于编辑器单元测试。

### `Battle/Map/BattleGridController.cs`

- 实现 `IVisionBlockerProvider`，提供地形、建筑占地和表面高度的逻辑查询。
- 建筑阻挡变化时通知视野系统，不让视野系统去遍历场景对象。

### `Battle/Vision/FogOfWarRenderer.cs`（新增）

- 在格子上方维护一张低分辨率 mask：未探索为黑，已探索为暗，可见为透明。
- 优先用一个网格/纹理渲染，不为每格创建新 `GameObject`。
- 使用双缓冲或材质插值平滑过渡，逻辑仍以离散格子为准。
- 手工 3D 地图和程序生成地图共用同一格子 mask，不逐个改动地形材质。

### `Battle/Vision/VisionPresentationController.cs`（新增）

- 订阅视野变化，统一设置敌军 `UnitView`、`CommanderMapMarker`、敌方血条和其他战斗反馈的显示状态。
- 隐藏只影响视觉和拾取，不停用单位根对象、AI、移动、占用或死亡流程。
- `UnitView` 提供 `SetFogVisible(bool)`，单独管理模型、血条和命中反馈，不与选中高亮相互覆盖。

### `Battle/Units/UnitSelectionController.cs`

- 敌方点击命中后先调用 `IsUnitVisible(TeamId.Player, unit)`。
- 视野外单位当作地面处理，不泄露敌人存在，不闪红、不显示“目标不可见”。

### `Battle/Commanders/CommanderGroupCommandController.cs`

- 玩家发起新 `AttackGroup` 时再做一次视野校验，防止 UI 和脚本入口绕过拾取层。
- 目标离开视野后，玩家编队完成已开始的当前攻击动作，然后停止并清除精确目标；MVP 不替玩家自动追踪最后已知位置。
- AI 仍由 `EnemyGroupAiController` 按其记忆状态调查最后已知位置。

### `Battle/AI/EnemyGroupAiController.cs`

- 保留现有记忆流程，改为消费新快照版本。
- 验证目标丢失、隐蔽强制遗忘、目标再发现和记忆过期不会重复发送命令。

### `Battle/Performance/BattleCore.cs`

- 在 `BattleVisionService` 后创建视野表现控制器与迷雾渲染器。
- 场景退出时取消订阅并释放临时纹理。

## 5. 分阶段实施

### 阶段 A：统一逻辑可见性

- 引入队伍格子快照、已探索记忆和查询 API。
- 先沿用当前圆形范围，暂不做遮挡和可见性表现。
- 把 AI、点击和攻击命令切换到统一查询。

验收：不可见敌人无法被玩家点选/攻击；AI 行为与改造前等价；隐蔽和嘲讽测试全部通过。

### 阶段 B：敌军可见性表现

- 接入敌方模型、指挥官头像、血条和选中/攻击反馈。
- 处理敌人在隐藏时移动、受伤、死亡和重新出现的状态同步。

验收：敌人离开视野后所有附属 UI 一起隐藏；重新进入视野时在新位置正确出现；不影响占用与战斗计算。

### 阶段 C：战争迷雾视觉

- 完成三态 mask、增量刷新和平滑过渡。
- 对测试地图、程序地图和手工 3D 地图分别验证边界、地表高度与渲染排序。

验收：三类地图都没有漏光、闪烁、遮挡 HUD 或遮挡己方单位的问题。

### 阶段 D：地形与建筑遮挡

- 接入确定性格子 LOS、阻挡配置和脏区更新。
- 森林采用视距成本，山脉/建筑采用完全阻挡。

验收：同一地图、单位位置和种子每次计算结果完全一致；阻挡格可见但其后方不可见。

### 阶段 E：性能、调试与平衡

- 添加 Scene 视图调试开关：可见格、探索格、视线阻挡格、编队视野半径和快照版本。
- 记录视野重算数、计算耗时、变化格数和每帧纹理上传次数。
- 调整各兵种 `VisionRange`、森林成本、AI 记忆时长和迷雾深浅。

验收：目标规模下无每帧 GC，慢 Tick 无可感知尖峰，视野表现不逐格创建对象。

## 6. 必测用例

1. 两支玩家指挥官编队相隔较远，玩家可见区是两者并集；切换激活指挥官不改变已探索结果。
2. 侦察单位移动后新区域变为可见，旧区域退为已探索，不回到未探索。
3. 敌人从未探索区域进入视野时模型、血条、头像同步出现；离开时同步隐藏。
4. 直接调用命令 API 也不能攻击当前不可见敌人。
5. 敌人离开视野后，玩家编队停止精确追踪；敌方 AI 仍按记忆前往最后已知位置。
6. 隐蔽编队不可见；触发近距离破隐或嘲讽强制暴露后立即可见；强制暴露不揭开周边地形。
7. 山脉和建筑阻挡后方视线，阻挡物本身可见；走到侧面后能正确发现目标。
8. 敌人在不可见时死亡，不在重新探索时残留头像、血条、选中环或空引用。
9. 直接打开 `BattleScene` 的 fallback 编队也能初始化视野与迷雾。
10. 测试地图、程序地图和手工 3D 地图都通过相同逻辑测试。

## 7. 实施顺序与估算

| 阶段 | 建议工作量 | 依赖 |
| --- | --- | --- |
| A 统一逻辑 | 1–2 天 | 无 |
| B 敌军表现 | 1–2 天 | A |
| C 迷雾渲染 | 2–3 天 | A |
| D 地形 LOS | 2–3 天 | A，建议在 C 后 |
| E 性能与平衡 | 1–2 天 | A–D |

总计约 7–12 个开发日，不包含额外迷雾美术、新技能和小地图。建议每个阶段单独编译、跑 EditMode 测试、进入战斗场景验证，不一次合并所有改动。

## 8. 完成定义

- 逻辑可见性只有一个事实来源，玩家、AI、技能和表现层不各自计算。
- 视野以指挥官编队为归属边界，不改变战斗中“一次激活一名指挥官、编队整体下令”的规则。
- 未探索、已探索和当前可见的表现稳定，敌军显示与命令权限一致。
- 隐蔽、强制暴露、AI 记忆、单位死亡与多编队共享视野均有自动测试覆盖。
- 目标战斗规模下无每帧全场遍历、无逐格对象刷新、无可感知的视野尖峰。
