# 建筑与兵工厂系统设计文档

## 1. 文档目标

本文定义战斗局内新增建筑单位与扩展军事单位的玩法、数据、UI 和分阶段实现方案。

本次需求包含两个建筑单位：

- 楼房：被占领后周期性产出金币。
- 兵工厂：被占领后可消耗金币生产陆地军事单位。

同时补充军事单位类型：

- 步系兵种：可占领建筑。
- 视野兵种：提供更大侦察视野，可与其他类型复合，例如侦察兵、侦察车。
- 远程机械：超远程、大范围、高威力、低攻速，存在 2-3 格近身盲区。
- 近程机械：坦克、大坦克等，用于攻击步兵和中近距离压制。

本文只做玩法与 UI 设计，不创建或修改 3D 模型、骨骼、动画和 Unity 场景对象。后续若制作建筑或单位模型，必须遵守 `规则/BlenderMCP工作规则.md`；若通过 Unity 编辑器落地场景、Prefab 或 UI，必须遵守 `规则/UnityMCP使用规则.md`。

## 2. 设计边界

本文与 `规则/指挥官编队玩法完善规则.md` 同时生效。涉及选择、移动、攻击、占领和生产后的单位归属时，必须遵守以下原则：

- 战斗中默认一次激活一名指挥官编队。
- 玩家命令由当前激活指挥官编队整体执行。
- 不允许退回到单兵直接控制。
- 普通单位可以拥有“占领能力”或“生产来源”，但玩家输入仍通过编队命令层路由。
- 新生产单位必须归属到某个 `CommanderGroupRuntime`，并获得稳定的 `CommanderGroupId`、槽位与生成顺序。
- 建筑不属于任何指挥官编队，不进入 `CommanderGroupRegistry`。建筑的归属、占领和生产由独立的 `BuildingRegistry` 与建筑运行时管理，与单位注册表按格隔离，避免同格双注册。
- 建筑归属使用独立枚举 `BuildingOwner`（`Neutral`/`Player`/`Enemy`）建模，不改动 `TeamId`（保持 `Player`/`Enemy`），避免波及单位 AI、视野与战斗判定。
- 建筑不可被攻击、不可被摧毁。MVP 中建筑的唯一交互方式是占领（含占领敌方建筑使其易主）。生产订单在建筑易主时取消并全额返还下单方金币（见 §10.1）。

截图 `D:/prounity/mvp/兵工厂/兵工厂.png` 作为兵工厂弹窗 UI 参考：左侧单位列表、价格、右侧单位预览、属性、克制信息和确认按钮。截图中的具体数值、单位列表和克制关系不是强制最终配置，以本文定义为准。

## 3. 核心循环

```text
步系编队接近中立或敌方建筑
  -> 发出占领建筑命令
  -> 占领进度持续累计
  -> 建筑归属变更为该指挥官/阵营
  -> 楼房开始周期产出金币
  -> 兵工厂开放生产 UI
  -> 消耗金币下达生产订单
  -> 生产完成后在兵工厂附近生成单位
  -> 单位加入生产时选择的己方指挥官编队
```

## 4. 建筑单位

### 4.1 通用建筑属性

建筑是战斗地图上的可交互单位，但不参与普通编队移动。

| 字段 | 说明 |
| --- | --- |
| `BuildingId` | 场内唯一 ID，例如 `building_factory_01` |
| `BuildingType` | `House`、`Armory` |
| `OwnerTeam` | 独立枚举 `BuildingOwner`：`Neutral`/`Player`/`Enemy` |
| `OwnerCommanderGroupId` | 记录最后完成占领的编队；中立时为空 |
| `Cell` / `Footprint` | 所在格与占地范围 |
| `MaxHealth` / `Health` | 预留字段；MVP 建筑不可被攻击，不承受伤害，本字段 MVP 不使用 |
| `CaptureProgress` | 当前占领进度（按阵营独立累加，见 §5.2） |
| `CaptureRequiredSeconds` | 占领所需时间 |
| `CanProduceGold` | 是否产金 |
| `CanProduceUnits` | 是否可生产单位 |
| `IsOperational` | 是否可工作；未占领时为 false（建筑不可被摧毁） |

建筑归属优先绑定阵营，同时记录最后完成占领的指挥官编队。金币进入玩家全局资源池；兵工厂生产单位在下单时选择加入任意己方未失败且有空槽的指挥官编队。

建筑的落地规则：

- 建筑 `Footprint` 覆盖的格视为不可行走且不可被单位占用：寻路、编队槽位校验和单位生成必须拒绝建筑格。建筑被占领后仍保持占用；建筑本局始终存在，不会被移除。
- 建筑恒可见，是静态地标，不参与视野遮蔽。归属通过阵营旗帜/颜色显示，中立建筑显示中立样式。
- 建筑不在 `UnitSelectionController._byCell` 中注册，另建 `BuildingRegistry`（按 `Footprint` 格映射到建筑），避免与单位注册表同格双注册。
- 建筑不可被攻击、不可被摧毁，不承受伤害；`MaxHealth`/`Health` 仅作预留。
- `OwnerCommanderGroupId` 同时作为兵工厂生产的默认接收编队（见 §10.2）。

### 4.2 楼房

楼房的定位是地图经济点。未占领时不产出金币；被步系兵种占领后进入周期产金。

建议 MVP 参数：

| 参数 | 建议值 |
| --- | --- |
| 占领时间 | 5 秒 |
| 产金间隔 | 10 秒 |
| 每次产金 | 500 |
| 最大储存 | 不储存，直接进入玩家金币 |
| 被敌方占领后 | 原归属失效，产金转给新阵营 |
| 摧毁规则 | 楼房不能被摧毁，只允许占领和易主 |

产金必须使用计时器或低频事件，不允许每帧遍历全部建筑刷新 UI。建议由 `BuildingEconomyController` 每秒 tick 一次，或由建筑自身维护下一次产出时间。

### 4.3 兵工厂

兵工厂的定位是局内生产建筑。只有被玩家占领后，玩家才能点开兵工厂 UI 并生产陆地军事单位。

建议 MVP 参数：

| 参数 | 建议值 |
| --- | --- |
| 占领时间 | 7 秒 |
| 生产队列 | 1 个槽位 |
| 生产完成出口 | 兵工厂周围最近合法格 |
| 生产归属 | 生产时选择加入任意己方未失败且有空槽的指挥官编队 |
| 金币不足 | 禁用确认按钮并显示金币不足 |
| 出口被堵 | 暂停完成，等待可用格；不吞掉金币 |
| 默认接收编队 | 兵工厂 `OwnerCommanderGroupId` 对应编队（见 §10.2） |

兵工厂不可被攻击、不可被摧毁。兵工厂在建筑易主（被敌方占领）时，其生产队列中的在途订单取消并全额返还下单方金币（见 §10.1）。

后续可扩展多队列、升级科技和生产加速；建筑维修与摧毁机制不纳入当前设计。

## 5. 占领规则

### 5.1 谁能占领

只有带有 `CanCaptureBuilding` 标签的步系单位可以推进占领进度。机械单位、远程机械和普通载具默认不能占领。

占领行为仍由当前激活编队发起：

```text
点击可占领建筑
  -> 当前激活编队收到 CaptureBuilding 命令
  -> 编队中具备占领能力的成员移动到建筑邻接格
  -> 到位后持续占领
```

同一编队内多名步系单位可加速占领，但设置有效占领单位上限，MVP 默认 `4`（3+ 按 §5.2 倍率封顶），避免大量单位瞬间夺点。

占领命令的成员槽位不属于普通阵型：参与占领的步系成员移动到建筑 `Footprint` 邻接格（占领槽位按建筑计算，不沿用编队锚点阵型）；不参与占领的成员原地保持当前锚点阵型。占领取消或结束后，参与成员通过 `Regroup` 回到各自锁定槽位。

### 5.2 进度计算

建议公式：

```text
每秒进度 = 基础占领速度 × 有效占领单位数量 × 状态修正
```

MVP 配置：

| 有效占领单位数 | 速度倍率 |
| --- | --- |
| 1 | 1.0 |
| 2 | 1.5 |
| 3+ | 2.0 |

进度累计规则（MVP）：

- 基础占领速度：1 个有效单位时每秒累计 `1.0 / CaptureRequiredSeconds` 点进度，即单单位占领耗时等于 `CaptureRequiredSeconds`。
- 双方各维护独立累加器 `CaptureProgressPlayer` 与 `CaptureProgressEnemy`，范围 `0..CaptureRequiredSeconds`。
- 仅当某方存在 ≥1 个邻接的有效占领单位，且对方无有效占领单位邻接时，该方进度累计；双方同时邻接时双方进度均暂停并显示争夺状态。
- 某方进度达到 `CaptureRequiredSeconds` 时建筑归属翻转为该方，双方累加器同时清零，重新开始累计。
- 反向夺回即原归属方再次累计进度并达到阈值后夺回，无需特判。
- 占领单位全部离开邻接格或被击杀：对应方进度暂停但保留（MVP 不做衰减）。
- 占领单位被攻击时进度继续，但单位可被击杀打断；被击杀的单位不再计入有效占领单位数。

### 5.3 编队状态与命令

新增编队命令类型 `CaptureBuilding`（战术命令，由编队命令层路由）。

`ProduceUnit` 不作为编队命令：生产由兵工厂 UI 发起，属于建筑动作，通过 `BuildingController` 直接创建生产订单，不经过编队命令层。

`CommanderGroupState` 新增 `Capturing`。合法转换：

```text
Idle -> Capturing              // 发占领命令
Capturing -> Moving            // 收到移动命令，取消占领并归位
Capturing -> Attacking         // 收到攻击命令，取消占领并归位
Capturing -> Holding           // 收到停止命令，取消占领并归位
Capturing -> Idle              // 占领完成或取消后归位完成
Capturing -> Defeated
```

`CaptureBuilding` 执行规则：

- 只允许具备 `CanCaptureBuilding` 的成员参与，占领槽位按建筑 `Footprint` 邻接格计算（不沿用编队锚点阵型）。
- 不参与占领的成员原地保持当前锚点阵型。
- 收到移动、攻击、停止或 `Regroup` 命令时，立即取消占领并让参与成员回到各自锁定槽位。
- 占领完成后编队回到 `Idle`，参与成员通过 `Regroup` 归位。

建筑拾取优先级：

```text
UI 弹窗
  -> 建筑 Footprint
  -> 指挥官地图头像
  -> 单位
  -> 地面格
```

- 点击己方已占领兵工厂：打开生产 UI。
- 点击中立或敌方建筑：若当前编队有步系单位则发出 `CaptureBuilding`；否则显示"需要步系单位占领"。
- 点击己方楼房：无操作或显示建筑归属信息（MVP 仅显示归属）。

## 6. 金币系统

金币是玩家阵营级资源，不属于单个士兵。UI 顶部显示当前金币，参考兵工厂截图左上角金币展示。

金币来源：

- 初始金币。
- 已占领楼房周期产出。
- 后续战斗奖励或卡牌效果。

金币消耗：

- 兵工厂生产陆地军事单位。
- 后续维修、升级或技能消耗。

建议 MVP 初始金币：`5000`。兵工厂 UI 打开时实时读取玩家当前金币，生产确认时再次校验，避免打开界面后金币变化导致负数。

新增 `BattleEconomyController`（单例）：

- 维护 `Player` 与 `Enemy` 各一份金币池，提供 `TrySpend(team, amount)` 原子校验扣减与 `GoldChanged` 事件。
- 楼房产金、兵工厂生产确认都通过它记账，禁止出现负数。
- 金币 UI 通过 `GoldChanged` 事件刷新，不每帧轮询。
- `BattleSimulationState.IsFrozen` 时禁止金币扣减与生产确认。
- 敌方与玩家使用同一套 `BattleEconomyController`，敌方初始金币见 §18.2。

## 7. 军事单位类型

### 7.1 单位分类标签

单位可以同时拥有多个标签：

| 标签 | 含义 |
| --- | --- |
| `Infantry` | 步系单位 |
| `CanCaptureBuilding` | 可占领建筑 |
| `Scout` | 视野单位 |
| `Vehicle` | 车辆 |
| `CloseMechanical` | 近程机械 |
| `LongRangeMechanical` | 远程机械 |
| `Transport` | 载具或运输单位 |

视野兵种采用复合标签，而不是单独互斥职业。例如侦察兵是 `Infantry + Scout + CanCaptureBuilding`，侦察车是 `Vehicle + Scout`。

迁移说明：删除 `UnitDefinition.CanCaptureCity`（bool）字段，统一以 `CanCaptureBuilding` 标签为唯一来源，并审计 `UnitCatalog`、部署与 AI 中所有读取点，避免双真相源。

### 7.2 建议单位池

| 单位 | 类型标签 | 价格 | 生产时间 | 定位 |
| --- | --- | --- | --- | --- |
| 步兵 | `Infantry`, `CanCaptureBuilding` | 1000 | 4 秒 | 低价占领、基础作战 |
| 机枪兵 | `Infantry`, `CanCaptureBuilding` | 3000 | 6 秒 | 反步兵、守点 |
| 侦察兵 | `Infantry`, `Scout`, `CanCaptureBuilding` | 2000 | 5 秒 | 大视野、可占领、弱战斗 |
| 侦察车 | `Vehicle`, `Scout` | 4000 | 7 秒 | 高速大视野、不可占领 |
| 坦克 | `Vehicle`, `CloseMechanical` | 7000 | 10 秒 | 近中程装甲压制 |
| 大坦克 | `Vehicle`, `CloseMechanical` | 12000 | 14 秒 | 高血量高伤害、速度慢 |
| 自行火炮 | `Vehicle`, `LongRangeMechanical` | 16000 | 16 秒 | 超远程、大威力、近身盲区 |
| 火箭炮车 | `Vehicle`, `LongRangeMechanical` | 18000 | 18 秒 | 范围伤害、低攻速、脆弱 |

价格可参考截图中的木牌价格层级，但以上数值更贴合新增类型完整性。

MVP 单位身份统一使用 `UnitType` 枚举（与 `UnitCatalog`、`UnitSpawner`、`StartingUnitEntry` 保持一致），生产订单同样引用 `UnitType`，不引入第二套字符串 ID（§13 的 `UnitDefinition.Id` 仅作展示/日志用途，MVP 以枚举为稳定身份）。

为支持上述单位，`UnitType` 枚举扩展为：`Infantry`、`MachineGunner`、`Scout`、`ScoutCar`、`Tank`、`HeavyTank`、`SelfPropelledArtillery`、`RocketArtillery`（枚举命名可配置，但 MVP 以枚举作为稳定身份）。

### 7.3 远程机械盲区

远程机械必须同时配置最大射程和最小射程：

| 参数 | 自行火炮建议值 |
| --- | --- |
| 最小射程 | 3 格 |
| 最大射程 | 8 格 |
| 攻击范围 | 目标格半径 1 格 |
| 攻击间隔 | 4 秒 |
| 单发伤害 | 高 |
| 不能攻击 | 距离 0-2 格目标 |

当敌人进入盲区时，远程机械不应直接开火。编队 AI 或玩家需要通过移动、近程机械保护或步兵拦截解决。

最小射程接入战斗链路：

- `UnitCombatController.InAttackRange` 改为同时判断 `距离 >= AttackRangeMin` 且 `距离 <= AttackRangeMax`。
- 编队战斗锚点搜索（`FindCombatAnchor`）与成员射程覆盖判断需排除最小射程内目标，不能把编队推进到只能打盲区的位置。
- 单位射程展示为环形（扣除中心盲区），不能把盲区格标为可攻击。
- 敌方 AI 对远程机械的感知与目标分配同样遵守最小射程。

### 7.4 近程机械

近程机械用于压制步兵和承受前线火力。

| 单位 | 射程 | 特点 |
| --- | --- | --- |
| 坦克 | 3 格 | 均衡，克制步兵和轻车 |
| 大坦克 | 3 格 | 高血量，高伤害，低速度 |

近程机械默认不能占领建筑，避免坦克单独夺点破坏步兵价值。

## 8. 克制关系

克制关系用于 UI 展示和战斗数值修正。兵工厂弹窗右侧可以展示“克制单位”和“被克制单位”。

建议 MVP 克制表：

| 单位类型 | 克制 | 被克制 |
| --- | --- | --- |
| 步兵 | 建筑占领、远程机械近身 | 机枪兵、坦克 |
| 机枪兵 | 步兵、侦察兵 | 坦克、远程机械 |
| 侦察兵 | 视野、占领 | 大多数战斗单位 |
| 侦察车 | 视野、快速探路 | 坦克、火炮 |
| 坦克 | 步兵、机枪兵、侦察车 | 大坦克、远程机械 |
| 大坦克 | 坦克、步兵 | 远程机械、被包围 |
| 自行火炮 | 坦克、大坦克 | 近身步兵、侦察车、坦克贴脸 |
| 火箭炮车 | 密集步兵、阵地 | 快速近身单位 |

MVP 克制采用"硬伤害倍率"一种落地方式：

- `UnitDefinition` 增加 `CounterTargets`（`UnitType` 列表）与 `CounterDamageMultiplier`（默认 `1.0`）。
- 攻击时若目标类型命中 `CounterTargets`，`Fire` 伤害乘以 `CounterDamageMultiplier`。
- 命中/溅射、规则限制、战术能力不作为 MVP 数值系统，仅作为单位设计意图与 UI 文案。

示例（数值可配置）：

- 坦克 `CounterTargets = [Infantry, MachineGunner, ScoutCar]`，`CounterDamageMultiplier = 1.25`。
- 大坦克 `CounterTargets = [Tank]`，`CounterDamageMultiplier = 1.5`。
- 自行火炮 `CounterTargets = [Tank, HeavyTank]`，`CounterDamageMultiplier = 1.5`。

## 9. 兵工厂 UI 设计

### 9.1 布局

参考 `兵工厂.png`，采用双栏木质面板：

```text
顶部：玩家金币、当前指挥官/占领归属

左栏：可生产单位列表
  - 单位头像
  - 单位名称
  - 金币价格
  - 生产时间
  - 不可生产状态：金币不足/科技未解锁/队列已满

右栏：当前选中单位详情
  - 3D 或 2D 预览
  - 生命、速度、视野、燃油/弹药等属性
  - 攻击范围、最小射程、攻速
  - 克制单位
  - 被克制单位

接收编队选择区：列出所有己方未失败编队（名称 + 存活数/9）
  - 满员项禁用并标注"编队已满"
  - 默认选中兵工厂 `OwnerCommanderGroupId` 对应编队；失败或满员时顺延（见 §10.2）

底部：确认生产、取消/关闭
```

### 9.2 必须显示的信息

兵工厂生产不是纯列表购买，必须让玩家知道单位用途：

- 单位名称。
- 价格。
- 生产时间。
- 当前金币。
- 是否可占领建筑。
- 是否为视野单位。
- 射程；远程机械必须显示最小射程。
- 速度和视野。
- 克制与被克制。
- 当前生产队列状态。
- 当前选中的接收编队与容量状态（如 `3/9`）。

### 9.3 交互规则

- 点击己方已占领兵工厂：打开兵工厂 UI。
- 点击中立或敌方兵工厂：若当前编队有步系单位，则发出占领命令；否则显示“需要步系单位占领”。
- 在 UI 左侧选择单位：右侧刷新详情。
- 金币足够且队列有空位：确认按钮可用。
- 确认前置条件：已选择接收编队、该编队未失败且存活数 `< 9`、金币足够、队列有空位。
- 未选择接收编队或全部满员：确认按钮禁用并显示原因。
- 点击确认：扣除金币并创建生产订单。
- 生产过程中：兵工厂地图上显示进度条或生产图标。
- 生产完成：在兵工厂出口生成单位，并加入生产时选择的己方指挥官编队。
- `BattleSimulationState.IsFrozen` 时确认按钮禁用。

### 9.4 关闭与输入穿透

UI 打开时地图点击不得穿透到战斗输入。点击取消或空白关闭时，不改变当前激活编队，不取消已存在生产队列。

## 10. 生产与归属

### 10.1 生产订单

建议数据：

```csharp
public sealed class ProductionOrder
{
    public string OrderId;
    public string BuildingId;
    public UnitType UnitType;   // MVP 以 UnitType 枚举为稳定单位身份（见 §7.2）
    public string OwnerCommanderGroupId;
    public int GoldCost;
    public float DurationSeconds;
    public float RemainingSeconds;
}
```

订单创建时立即扣金币。

- 若建筑易主（被敌方占领）：在途订单取消并全额返还下单方金币。
- 若只是出口被堵：订单完成但暂不生成，等待出口可用。
- 建筑不可被摧毁，不存在因摧毁取消订单的情况。

### 10.2 新单位加入方式

MVP 规则：新生产单位允许选择加入任意己方未失败且有空槽的指挥官编队。

默认接收编队优先级（UI 初始选中与下单默认值）：

1. 兵工厂 `OwnerCommanderGroupId` 对应编队（即占领并在该兵工厂生产的指挥官编队）；该编队失败或满员时顺延。
2. 当前激活编队（若未失败且有空槽）。
3. 其余任意未失败且有空槽的己方编队，按 `RosterIndex` 顺序。

原因：

- 符合当前编队玩法规则。
- "谁造的兵归谁"符合直觉，同时保留把产能汇入前线编队的灵活性。
- 避免新增"无归属单位池"的复杂 UI。

#### 10.2.1 归队流程（新生产单位加入）

新生产单位生成在兵工厂出口最近合法格后，必须归入接收编队锁定阵型，否则成员位置不等于 `锚点 + 槽位偏移`，会卡死编队移动与到达判定：

- 生成时立即分配接收编队下一个空闲 `FormationSlotIndex`，并把 `UnitSlotAssignments` 绑定写入该编队 `Layout`。
- 单位进入"归队中"状态（`IsReturningToFormation = true`）：自动按编队速度行军到 `AnchorCell + SlotOffsets[slot]`。
- 归队期间不参与 `AtLockedSlots` 判定，不阻塞编队其他命令；编队移动/攻击时按普通成员重新计算目标槽位。
- 归队途中若接收编队被击败，单位随编队销毁。
- 到达槽位后清除 `IsReturningToFormation`，转为正常成员，参与移动/攻击/阵型判定。
- 归队路径被堵：持续重试，不影响编队其他命令；出口被堵同样适用 §4.3 出口等待规则。

后续可扩展：

- 生产单位进入预备队，战斗间隙编入。
- 建筑归属阵营级，单位由最近指挥官接收。

### 10.3 阵型槽位容量

当前规则中每个指挥官编队部署槽位为 3×3，最多容纳 9 个存活单位。生产系统必须处理容量限制：

- 若选择的目标编队未满：单位加入编队，并分配空槽。
- 若选择的目标编队已满：生产按钮显示“编队已满”，禁止下单。
- 后续若设计后备队，可允许下单但单位进入预备队；MVP 不建议。

满员判定以 `AliveMemberCount >= 9` 为准（3×3 槽位全部占用）；归队中的成员计入存活数。

## 11. 战斗与 AI 接入

敌方在 MVP 同步使用建筑经济和兵工厂生产，但实现时仍应分步骤接入，避免一次性叠加过多风险。

建筑不可被攻击，敌我双方对建筑的唯一交互是占领（含占领敌方建筑使其易主）。

推荐阶段：

1. 玩家可占领中立建筑，获得金币和生产。
2. 敌方可拥有初始建筑，并通过同一套全局阵营金币生产单位。
3. 敌方 AI 可占领建筑。
4. 敌方 AI 可按金币、队列和编队容量生产单位。

敌方 AI 必须通过同一套编队命令接口占领建筑，不能直接改建筑归属或瞬间刷单位。

### 11.1 敌方经济与占点/生产 AI

- 新增或扩展 AI 组件（可挂在现有 `EnemyGroupAiController` 旁）：`EnemyBuildingAiController`。
- 占点决策（SlowTick）：若某个敌方编队有 `CanCaptureBuilding` 成员，且存在可占领建筑（中立或玩家拥有），按距离与权重发 `CaptureBuilding`；优先级与冷却见 §18.4。
- 生产决策：每个敌方兵工厂每 `3-5 秒` 做一次决策（§18.4 权重表），校验金币、队列状态与接收编队容量；没有可接收编队时暂停生产。
- 敌方生产单位同样走 §10.2.1 归队流程，归属敌方编队。
- 敌方 MVP 不主动摧毁玩家建筑（建筑不可被攻击，无法摧毁）。
- 所有金币通过 `BattleEconomyController` 记账，禁止直接改数值。

## 14. 分阶段实施方案

### 阶段 A：数据与 UI 文档落地

- 建立建筑和单位配置：扩展 `UnitType` 枚举与 `UnitDefinition` 字段；迁移 `CanCaptureCity` -> `CanCaptureBuilding` 标签。
- 建立兵工厂 UI 静态界面（含接收编队选择器，先用假数据）。
- 列表、详情、价格、属性和克制关系可展示假数据。

验收：打开兵工厂 UI 后能选择不同单位并刷新详情；接收编队选择器显示各编队容量状态。

### 阶段 B：占领与楼房产金

- 实现建筑归属（`BuildingOwner` 枚举）与 `BuildingRegistry`。
- 建筑放置接入地图生成（`BuildingSpawnData`）。
- 实现步系编队占领命令：`CaptureBuilding` + `Capturing` 状态机 + 占领槽位 + 独立累加器进度。
- 实现楼房周期产金（`BattleEconomyController`）。

验收：步系单位占领楼房后，金币按 CD 增加；非步系单位不能占领；双方争夺时进度暂停。

### 阶段 C：兵工厂生产

- 实现生产订单（以 `UnitType` 为单位身份）。
- 金币扣除与不足校验（`BattleEconomyController`）。
- 实现归队流程（§10.2.1）与目标编队容量校验。
- 实现建筑易主时在途订单取消并全额返还。
- 生产完成生成单位并加入归属编队。

验收：占领兵工厂后可消耗金币生产步兵或坦克，单位获得正确 `CommanderGroupId`，并自动归入接收编队阵型。

### 阶段 D：扩展单位类型

- 加入侦察兵、侦察车。
- 加入远程机械最小射程和范围伤害（`InAttackRange` 双射程、射程环、范围伤害）。
- 加入大坦克等近程机械。
- 实现克制硬伤害倍率。

验收：视野单位影响感知范围；远程机械不能攻击 2-3 格内目标；克制倍率在战斗伤害中生效。

### 阶段 E：AI 与平衡

- 敌方可争夺建筑。
- 敌方通过 `BattleEconomyController` 与 `EnemyBuildingAiController` 生产。
- 调整价格、生产时间、射程和克制倍率。

验收：敌我双方围绕建筑形成可持续争夺。

## 15. 必测用例

1. 中立楼房未占领时不产金币。
2. 步兵编队占领楼房后，金币每隔固定 CD 增加。
3. 坦克编队点击中立楼房时，占领失败并提示需要步系单位。
4. 占领中的步兵离开建筑邻接格后，占领进度暂停。
5. 双方步系单位同时争夺同一建筑时，占领进度暂停。
6. 玩家占领兵工厂后，点击兵工厂打开生产 UI。
7. 金币不足时，生产确认按钮禁用。
8. 金币足够时，确认生产立即扣金币并创建订单。
9. 生产完成后，单位生成在兵工厂附近合法格。
10. 新单位拥有所选目标编队的正确 `CommanderGroupId`，不会变成可被单独控制的游离单位。
11. 所选目标编队已满时，兵工厂不能继续生产加入该编队的单位。
12. 远程机械面对 2 格内敌人时不能攻击，面对 3 格外敌人可以攻击。
13. 侦察兵和侦察车的视野大于普通单位。
14. UI 打开时点击地图不会下达移动或攻击命令。
15. 生产单位加入远处有空槽编队后自动归队，归队期间编队其他命令不卡死；到达后正常参与战斗。
16. 建筑 `Footprint` 格不可行走、不可部署、不可生成单位。
17. 中立建筑不可被攻击（无攻击命令），只能被占领。
18. 兵工厂易主时在途订单取消并全额返还下单方金币。
19. 建筑易主（含占领敌方兵工厂）后，原归属产金停止，新阵营开始产金。
20. 原归属方步系单位进入后按独立累加器反向累计，达到阈值夺回建筑。
21. 占点单位超过上限（默认 4）时按 §5.2 倍率封顶。
22. 兵工厂生产默认接收编队为 `OwnerCommanderGroupId` 对应编队；其满员时顺延到有空槽编队。
23. 克制倍率生效：坦克攻击步兵按 `CounterDamageMultiplier` 修正伤害。
24. 远程机械面对最小射程内目标不开火，面对射程环内目标正常开火。
25. 接收编队满 9 人时生产确认禁用并提示"编队已满"。
26. `BattleSimulationState.IsFrozen` 时兵工厂确认与 AI 生产被禁止。

- 远程机械必须支持 `MinAttackRange` 和 `MaxAttackRange` 两个独立配置字段。

| 自行火炮 | 3 格 | 8 格 | 4 秒 | 1 格 | 远距离反坦克，怕近身 |
| 火箭炮车 | 4 格 | 9 格 | 5 秒 | 1.5 格 | 更强范围压制，更怕近身 |

必须可配置字段：

```text
AttackRangeMin
AttackRangeMax
AttackCooldown
AreaRadius
Damage
ProjectileSpeed
```

调参时优先调整顺序：先调 `AttackRangeMin` 和 `AttackRangeMax`，再调 `AttackCooldown`，最后调 `Damage`。不要一开始就用伤害硬调，否则容易掩盖射程体验问题。

### 18.4 敌方生产策略默认方案

敌方 MVP 不做复杂策略树，先使用权重表和冷却判断。

| 条件 | 行为 | 默认权重 |
| --- | --- | --- |
| 没有步系占领单位 | 优先生产步兵或侦察兵 | 40 |
| 己方可见敌方步兵多 | 生产机枪兵或坦克 | 25 |
| 己方可见敌方坦克多 | 生产大坦克或自行火炮 | 25 |
| 视野不足或找不到目标 | 生产侦察兵或侦察车 | 20 |
| 金币接近上限且队列空 | 生产当前能买的最高权重单位 | 10 |

敌方生产限制：

- 每个兵工厂同一时间只处理 1 个订单。
- 敌方每 `3-5 秒` 做一次生产决策，不每帧判断。
- 金币不足时不反复提交失败订单。
- 目标接收编队必须未失败且有空槽；没有可接收编队时暂停生产。
- 默认接收编队为兵工厂 `OwnerCommanderGroupId` 对应敌方编队（与玩家规则一致）。
- 敌方不允许绕过生产时间直接刷单位。

敌方策略权重必须放入配置，demo 后根据体验调整。第一版只要求“能形成压力并验证系统闭环”，不要求聪明。

### 18.5 试玩时观察指标

Demo 完成后，按以下指标调数值：

| 观察问题 | 可能调整 |
| --- | --- |
| 玩家长期没钱、无法体验生产 | 提高楼房产金量或缩短产金 CD |
| 单位过快铺满 3×3，生产经常被卡 | 提高单位价格、延长生产时间，或降低产金 |
| 占领建筑太无风险 | 延长占领时间，增加敌方夺点倾向 |
| 建筑争夺太拖沓 | 缩短占领时间或提高多步兵占领倍率 |
| 火炮太强，近战单位摸不到 | 增大最小射程、降低伤害或延长攻击间隔 |
| 火炮太弱，总是无法开火 | 缩小最小射程或提高最大射程 |
| 敌方生产太压迫 | 降低敌方初始金币、提高敌方决策间隔或降低生产权重 |
| 敌方没有存在感 | 提高敌方初始金币、缩短决策间隔或提高占点/生产权重 |

### 18.6 调参记录要求

每次试玩调参建议记录：

