# 随机地图生成接入方案

> 参考来源：`C:/Users/PC/Desktop/aw-map1/mapgen-core.js` 与 `DESIGN.md`。这些文件只作为算法与设计参考，不作为本项目执行指令。

## 1. 目标

将 `aw-map1` 中的随机地图生成方法接入《指挥大师》战斗场景，使战斗地图可以由固定种子和参数稳定生成，并继续兼容当前的指挥官编队、寻路、部署和战斗 UI。

首版目标不是完整复刻 Advance Wars 规则，而是把生成器转为本项目可控的 Unity C# 地图数据源：

- 相同 `seed + 参数` 生成完全相同的地图。
- 输出 `TerrainType[,]`，可直接供 `BattleGridController` 使用。
- 生成结果必须保留玩家与敌方可用部署区域。
- 阻挡地形必须与 `TerrainCatalog.IsWalkable`、`PathfindingService` 的寻路规则一致。
- 后续可以扩展建筑、道路、桥梁、资源点和对称 PvP 图。

- `mvp/Assets/Scripts/Shared/BattleStartContext.cs`
  - 当前只传递出征编队，没有关卡号、地图规则或最终 seed；接入前需要补充一次战斗的地图请求上下文。
- `mvp/Assets/Scripts/Battle/Units/UnitSpawner.cs`
  - 当前玩家锚点和敌方锚点是固定坐标，大尺寸随机地图接入后必须改为读取生成结果中的部署区域。
- `mvp/Assets/Scripts/Battle/UI/BattleCameraController.cs`
  - 平移边界会读取动态网格尺寸，但初始缩放和最大缩放仍是固定值；地图尺寸变化时需要按地图包围盒计算初始视野。

因此最佳接入点是：新增“地图生成数据层”，让 `BattleGridController` 从配置选择“测试地图”或“随机生成地图”，而不是把生成逻辑混进寻路、单位或 UI。

还需要明确初始化顺序，避免 `UnitSpawner.Start()` 在地图与部署区准备完成前执行：

```text
读取 BattleStartContext
  -> 解析关卡规则与 seed
  -> 生成并校验地图
  -> BattleGridController 建立逻辑网格和视觉
  -> UnitSpawner 按部署区生成双方编队
  -> 相机/小地图按最终尺寸刷新
  -> 进入 Deployment 阶段
```

## 3. aw-map1 算法可复用内容

`mapgen-core.js` 的生成管线适合迁移为 C#：

1. `mulberry32`：可复现伪随机数。
2. `Perlin + fbm`：生成高度图与湿度图。
3. 地形分类：海洋、山地、森林、平原。
4. `smoothTerrain`：元胞自动机平滑，减少孤岛和零碎地形。
5. `carveRivers`：沿高度梯度雕刻河流，并保证四连通。
6. `addBeach`：海岸邻接格转沙滩。
7. `mirror180`：180 度旋转对称，用于公平对战图。
8. 建筑放置与道路桥梁：首版可先保留数据结构，暂不进入战斗逻辑。

需要注意：JS 中的 `TERRAIN` 枚举和本项目 `TerrainType` 不完全一致，不能直接复制数值。必须通过显式映射转换。

## 4. 地形映射建议

首版建议只映射到项目已有地形，不立即新增 `Road`、`Bridge`、`River` 枚举，避免扩大可视化、寻路和美术适配范围。

| aw-map1 地形 | 建议映射 | 通行性 | 说明 |
| --- | --- | --- | --- |
| `OCEAN` | `Ocean` | 不可通行 | 深水边界和大片水域 |
| `BEACH` | `Desert` 或 `ShallowWater` | 可通行 | 若偏陆地海岸用 `Desert`，若偏浅滩用 `ShallowWater` |
| `PLAIN` | `Plain` | 可通行 | 主战斗区域 |
| `FOREST` | `Forest` | 可通行 | 可后续加防御/移速权重 |
| `MOUNTAIN` | `Mountain` 或 `SnowMountain` | 建议可通行/阻挡分层 | 首版用 `Mountain`；若需要硬阻挡再用 `SnowMountain` |
| `RIVER` | `ShallowWater` | 可通行 | 当前无河流专属枚举，先作为浅水 |
| `ROAD` | `Plain` | 可通行 | 首版视觉不区分道路 |
| `BRIDGE` | `Plain` 或 `ShallowWater` | 可通行 | 首版可用 `Plain` 保证通过 |

如果下一阶段要表现道路/桥/河流，建议再扩展 `TerrainType`，并同步更新 `TerrainCatalog.GetColor/GetDisplayName/IsWalkable` 和地形贴图资源。

## 5. 推荐代码结构

新增目录：

```text
mvp/Assets/Scripts/Battle/Map/Generation/
```

建议类：

```text
MapGenerationSettings.cs
SeededRandom.cs
PerlinNoise2D.cs
GeneratedMapData.cs
ProceduralMapGenerator.cs
GeneratedTerrainMapper.cs
MapGenerationValidator.cs
LevelMapGenerationProfile.cs
LevelMapGenerationRule.cs
```

职责划分：

- `MapGenerationSettings`
  - 保存 `width`、`height`、`seed`、`seaLevel`、`mountainLevel`、`forestMoisture`、`rivers`、`smoothRounds`、`mirror` 等参数。
  - 可先做普通 `[Serializable]` 类，后续再升级为 `ScriptableObject`。
- `ProceduralMapGenerator`
  - 纯 C# 逻辑，无 `MonoBehaviour`，输入 settings，输出中间地形枚举与统计。
  - 从 JS 迁移 `mulberry32`、`Perlin`、`fbm`、平滑、河流、沙滩、镜像。
- `GeneratedTerrainMapper`
  - 将 aw-map1 风格地形转换为项目 `TerrainType[,]`。
- `MapGenerationValidator`
  - 检查尺寸、可通行比例、玩家/敌方部署区、连通性、对称性。
- `GeneratedMapData`
  - 保存 `TerrainType[,] Terrain`、宽高、最终 seed、生成器版本、统计信息、部署区、可选建筑/道路信息。
- `LevelMapGenerationProfile`
  - 关卡随机地图配置资产，保存多条“关卡范围 -> 地图参数”的规则。
  - 放在 `mvp/Assets/Resources/MapGeneration/` 或 `mvp/Assets/ScriptableObjects/MapGeneration/`。
- `LevelMapGenerationRule`
  - 单条规则，描述第几关到第几关使用哪套随机地图参数。
  - 包含关卡范围、seed 策略、地图尺寸、地形参数、校验阈值、重试次数等。

`BattleGridController` 增加一个地图来源选项：

```csharp
enum BattleMapSource
{
    TestMap,
    Procedural
}
```

在 `Awake()` 中根据来源选择：

```csharp
_terrain = _mapSource == BattleMapSource.Procedural
    ? _proceduralMapProvider.CreateTerrain()
    : TestBattleMapData.Create();
```

## 6. 随机地图测试工具计划

参考 `aw-map1/aw-map-generator.html` 的演示方式，建议在 Unity 中实现一个专用编辑器工具，而不是只做运行时代码。工具用于策划调参、预览地图、验证可玩性，并保存“多少关到多少关使用什么随机地图设置”的配置。

工具名称建议：

```text
随机地图配置工具
```

Unity 菜单入口：

```text
Tools/Map Generation/Random Map Tool
```

推荐文件：

```text
mvp/Assets/Editor/MapGeneration/RandomMapToolWindow.cs
mvp/Assets/Scripts/Battle/Map/Generation/LevelMapGenerationProfile.cs
mvp/Assets/Scripts/Battle/Map/Generation/LevelMapGenerationRule.cs
```

工具界面分三块：

- 左侧参数面板
  - 随机种子、地图宽高、玩法模式、是否生成建筑。
  - 海平面、山地高度线、森林湿度线、河流数量、桥跨河格数、平滑轮数。
  - 地形类型开关：海洋、沙滩、河流、森林、山地。
  - 校验参数：最小可通行比例、最大水域比例、最大阻挡比例、部署区尺寸、最大重试次数。
- 中间地图预览
  - 用颜色方格或贴图预览生成结果。
  - 鼠标悬停显示格子坐标、地形类型、是否可走、是否属于部署区。
  - 可显示玩家部署区、敌方部署区、中心线、镜像检查结果。
- 右侧关卡规则列表
  - 每条规则显示：`起始关卡`、`结束关卡`、规则名称、地图尺寸、模式、seed 策略。
  - 支持新增、复制、删除、上移、下移。
  - 支持选中某条规则后在左侧编辑参数。

工具还应包含两个不会直接改变配置的测试入口：

- “按关卡预览”：输入关卡号，显示实际命中的规则、派生 seed、生成器版本和 fallback 状态。
- “复现失败地图”：粘贴失败报告中的 seed 与参数快照，直接还原问题地图，避免配置后来变化后无法定位。

## 7. 关卡范围配置规则

核心需求是“多少关到多少关使用什么样的随机地图设置”。建议用 `ScriptableObject` 保存：

```csharp
[Serializable]
public sealed class LevelMapGenerationRule
{
    public string DisplayName;
    public int StartLevel;
    public int EndLevel;
    public MapGenerationSettings Settings;
    public SeedMode SeedMode;
    public int FixedSeed;
    public int RetryCount;
    public MapValidationSettings Validation;
}
```

`SeedMode` 建议：

```text
Fixed
LevelBased
ProfileSeedPlusLevel
RandomAtRuntime
```

含义：

- `Fixed`
  - 整个关卡段使用同一个 seed，适合手工挑选好图。
- `LevelBased`
  - 使用关卡号派生 seed，例如 `seed = levelIndex * 1009 + profileSalt`。
- `ProfileSeedPlusLevel`
  - 使用配置资产的基础 seed 加关卡号，适合整章保持风格但每关不同。
- `RandomAtRuntime`
  - 每次进入都随机，适合无尽模式；主线关卡不建议默认使用。

配置资产建议再增加：

```text
ProfileId          // 稳定 ID，不依赖资源文件名
ProfileVersion     // 配置版本，修改规则后递增
GeneratorVersion   // 算法版本，算法行为变化时递增
ProfileSalt        // 参与确定性 seed 派生
FallbackRule       // 没有命中或生成失败时使用
```

seed 不建议使用 `string.GetHashCode()` 派生，因为不同运行环境可能不稳定。应使用明确的整数混合函数，把 `ProfileSalt + levelIndex + attemptIndex + GeneratorVersion` 合成为 32 位 seed。

规则选择流程：

1. 进入战斗前取得当前关卡号 `levelIndex`。
2. 从 `LevelMapGenerationProfile.Rules` 中查找第一条满足 `StartLevel <= levelIndex <= EndLevel` 的规则。
3. 根据规则和 seed 策略生成最终 seed。
4. 调用 `ProceduralMapGenerator` 生成地图。
5. 调用 `MapGenerationValidator` 校验地图。
6. 校验失败则按 seed 派生规则重试，直到成功或达到 `RetryCount`。
7. 仍失败时回退到固定测试地图或该规则指定的 fallback seed。

每次战斗应记录一份轻量的 `GeneratedMapIdentity`：

```text
ProfileId + ProfileVersion + GeneratorVersion
LevelIndex + RuleId + FinalSeed + AttemptIndex
MapHash
```

存档、战斗复盘和错误日志保存这份身份信息。若以后算法升级，旧存档可以按旧生成器版本重建，或直接保存压缩后的最终地形数据作为兼容回退。

关卡段示例：

| 关卡范围 | 风格 | 推荐设置 |
| --- | --- | --- |
| 1-3 | 新手平原 | 小地图、少水、少山、无建筑、无对称 |
| 4-6 | 森林丘陵 | 增加森林和山地，河流 0-1 条 |
| 7-10 | 河流分割 | 河流 1-2 条，浅水可通行，校验必须有通路 |
| 11-15 | 大地图混合 | 24x18，更多地形变化，允许建筑标记 |
| 16+ | 高难对称/复杂图 | 可开启 180 度对称或更严格部署校验 |

## 8. 工具操作流程

策划或开发测试时的建议流程：

1. 打开 `Tools/Map Generation/Random Map Tool`。
2. 新建或加载一个 `LevelMapGenerationProfile`。
3. 新增关卡规则，例如 `1-5 新手地图`。
4. 调整左侧参数，点击“重新生成”即时预览。
5. 点击“随机种子”快速洗图，看到满意地图后可固定 seed。
6. 点击“批量验证”，对该规则测试 100 或 500 个 seed。
7. 工具显示成功率、失败原因统计、地形占比、路径连通性。
8. 保存配置资产。
9. 战斗场景按当前关卡号读取配置并生成地图。

批量验证应分帧或放到后台纯 C# 任务执行，并提供进度、取消和耗时显示，避免 500 个 seed 阻塞 Unity 编辑器。后台任务只处理纯数据，预览纹理和 `UnityEngine.Object` 更新仍回到主线程。

工具按钮建议：

```text
重新生成
随机种子
验证当前地图
批量验证当前规则
批量验证全部规则
保存配置
导出预览 PNG
应用到 BattleScene 预览
```

其中“应用到 BattleScene 预览”如果需要直接改 Unity 场景对象，应遵守项目 Unity MCP 使用规则；普通代码实现和文档计划阶段不需要通过 Unity MCP。

## 9. 工具验收标准

首版工具完成后应满足：

- 可以创建、编辑、保存 `LevelMapGenerationProfile`。
- 可以配置多条不重叠的关卡范围规则。
- 输入关卡号后能显示命中的规则。
- 同一关卡号和同一配置生成结果稳定。
- 地图预览能显示地形、部署区和基础统计。
- 校验失败时显示具体原因，例如“玩家部署区不足”“双方无通路”“水域比例过高”。
- 批量验证能输出成功率。
- 批量验证不会长时间卡死编辑器，并可中途取消。
- 验证报告可导出，至少包含失败 seed、规则 ID、失败原因、尝试次数和地图哈希。
- 战斗运行时能根据关卡号选中规则并生成地图。

关卡范围还需要做数据校验：

- `StartLevel >= 1`。
- `EndLevel >= StartLevel`。
- 同一个 profile 内规则不能重叠。
- 可以允许规则之间有空档，但工具必须提示；运行时空档关卡使用 fallback 规则。
- 每条规则必须有稳定 `RuleId`；复制规则时生成新 ID，调整显示名称时不改变 ID。
- 规则按范围查找，不依赖列表顺序决定冲突结果；存在重叠时禁止保存或禁止进入 Play Mode。

## 10. 与指挥官编队规则的关系

随机地图接入不能破坏“战斗中一次激活一名指挥官，并由其麾下单位整体执行命令”的规则。地图生成只负责格子，不负责直接生成或控制单位。

必须保留以下边界：

- 生成器不直接创建士兵、指挥官或 `CommanderGroupRuntime`。
- 生成器可以输出推荐部署区域，但实际单位生成仍由战斗生成/部署系统读取。
- 每名出征指挥官需要独立部署区域，区域之间不得共享可放置格。
- 对称地图用于 PvP 或公平 AI 场景时，要同时验证双方部署区域和通路。

推荐在生成结果中加入：

```text
PlayerDeploymentCells
EnemyDeploymentCells
NeutralObjectiveCells（可选）
```

首版可以用固定区域规则推导：

- 玩家：地图左下或下侧 3x3/多编队区域。
- 敌方：地图右上或上侧对应区域。
- 若 `mirror = true`，敌方区域由玩家区域 180 度镜像得到。

部署校验不能只统计可用格数量，还要验证每支编队能放下一个实际的连续阵型。首版至少应对当前 3x3 最大阵型做模板匹配，并在多指挥官情况下分配互不重叠、彼此留有间隔的部署块。`UnitSpawner` 应接收已分配的锚点/槽位，不能再用固定坐标后向外搜索，否则可能把同一编队打散或生成到敌方区域。

## 11. 验证规则

每次生成后必须做自动校验，失败则换 seed 或回退测试地图。

最低校验：

- 宽高在允许范围内，例如 16x14、24x18、32x24。
- 可通行格比例建议在 55% 到 85%。
- 玩家部署区至少容纳出征指挥官的 3x3 编队需求。
- 敌方部署区至少容纳敌方初始单位。
- 玩家部署区与敌方部署区之间存在至少一条可通行路径。
- 不允许关键部署格落在 `Ocean` 或 `SnowMountain`。
- 对称模式下，逐格验证 `terrain[y,x] == terrain[h-1-y,w-1-x]`。
- 玩家和敌方部署区到主要交战区均有出口，不能被单格瓶颈完全封死。
- 校验器的邻接规则必须与运行时寻路一致；当前为 8 方向 A*，还需明确是否允许斜向穿过两个阻挡格的夹角。

进阶校验：

- 森林/山地/水域占比不能极端偏高。
- 中央区域必须有可交战通道。
- 河流不应完全切断地图，除非存在桥或浅水通路。
- 多名指挥官出征时，各自初始 3x3 区域不能重叠。
- 对双方计算最短路长度与可达面积，避免地图虽然“连通”但一方路程明显更短。
- 对称/公平模式检查资源点、部署容量和关键区域距离，而不只检查地形逐格对称。
- 对最大地图做格子视觉对象数量、构建耗时和寻路耗时预算；若格子对象过多，应考虑网格合批或分块渲染。

## 12. 实施阶段

### 阶段一：纯算法迁移

- 将 `mapgen-core.js` 的核心算法翻译为 C#。
- 写一个编辑器或普通测试入口，对固定 seed 生成地图统计。
- 暂不接入战斗场景。

验收：

- 同 seed 多次生成结果一致。
- 不同 seed 结果明显不同。
- 生成 100 个 seed 不报错。
- 固定 golden seed 的地图哈希稳定，用于发现算法行为被意外改动。

### 阶段二：编辑器测试工具

- 实现 `LevelMapGenerationProfile` 与 `LevelMapGenerationRule`。
- 实现 `RandomMapToolWindow`。
- 支持调参、预览、统计、批量验证、保存配置。
- 暂不强制接入战斗流程。

验收：

- 能配置 `1-5`、`6-10` 这类关卡段。
- 选中不同关卡段时，预览参数随规则变化。
- 批量验证能列出失败 seed 和失败原因。

### 阶段三：接入 `BattleGridController`

- 增加地图来源配置。
- 保留 `TestBattleMapData` 作为回退。
- 随机地图输出 `TerrainType[,]` 后由现有 `BuildVisual()` 渲染。
- 不改 `PathfindingService`。
- 增加统一的战斗地图启动协调器，保证地图完成后才生成单位和刷新相机/小地图。

验收：

- 战斗场景能显示随机地形。
- 单位移动仍走 `IGridDataProvider`。
- 海洋/阻挡地形不可走。
- 16x14、24x18、32x24 下相机均能正确居中、平移和缩放。

### 阶段四：关卡号驱动随机地图

- 在 `BattleStartContext` 或独立 `BattleMapRequest` 中传入当前关卡号；当前工程尚无此字段，这是本阶段的前置改动。
- 根据 `LevelMapGenerationProfile` 查找对应规则。
- 生成并校验地图，失败按规则重试。
- 仍失败时回退固定地图或 fallback seed。

验收：

- 第 1-5 关使用新手地图参数。
- 第 6-10 关自动切换为下一套地图参数。
- 同一关卡号在同一配置下生成稳定。
- 日志能输出规则 ID、最终 seed、尝试次数和地图哈希，可一键在工具中复现。

### 阶段五：部署区与编队适配

- 生成或推导玩家/敌方部署区。
- 与多指挥官出征名单、3x3 编队规则对齐。
- 开战前验证全部编队区域合法。

验收：

- 多名指挥官不重叠生成。
- 点击/移动/攻击仍走编队命令层。
- 随机地图不会导致开局单位卡死。

### 阶段六：建筑、道路、桥梁扩展

- 根据需要新增 `Road`、`Bridge`、`River`、`City` 等逻辑或对象。
- 建筑先作为地图标记，不直接混入单位系统。
- 道路/桥梁可以影响移动代价，但这需要扩展 `PathfindingService` 的成本接口。

验收：

- 建筑数量和位置可复现。
- 对称模式双方资源完全一致。
- 道路/桥梁视觉与通行规则一致。

## 14. 风险与处理

- **JS 到 C# 随机数差异**：不追求与 JS 像素级一致，追求 C# 内部可复现。若必须复刻 JS 输出，需要严格使用 `uint` 溢出语义实现 `mulberry32`。
- **地图美术不匹配**：首版使用现有 `TerrainCatalog` 颜色和地形贴图占位，后续再绑定斜视角 2D 资源。
- **河流阻断寻路**：首版把河流映射为 `ShallowWater`，避免生成不可解地图；后续有桥梁系统后再提高阻挡性。
- **多编队部署空间不足**：生成后做批量校验，失败换 seed，不允许生成一半后进入战斗。
- **建筑系统过早接入**：先保留建筑网格数据，不接经济/生产玩法，避免牵连战斗主循环。
- **工具参数过多难用**：首版提供“新手平原、森林丘陵、河流分割、大地图混合”预设，策划先选预设再微调。
- **关卡范围冲突**：保存 profile 前强制检查重叠，运行时只接受已验证配置。
- **随机运行不可复盘**：主线关卡默认使用关卡号派生 seed，无尽模式才使用真正运行时随机。
- **算法升级破坏旧存档**：保存生成器版本与地图身份；版本不兼容时读取已保存的最终地形数据。
- **固定出生点越界或破坏编队**：移除 `UnitSpawner` 的硬编码锚点，改为消费生成器已验证的连续部署块。
- **大地图镜头和小地图异常**：地图构建完成后广播尺寸变化，统一刷新相机边界、初始缩放和小地图纹理。
- **批量测试卡住编辑器**：纯数据批处理分帧/后台运行，提供取消，并限制单次预览刷新频率。
- **配置改动污染复现结果**：规则使用稳定 ID，报告同时保存参数快照、版本和地图哈希。

## 15. 建议补充的性能与质量门槛

首版应先定义可测量门槛，具体数值可在目标设备实测后调整：

| 项目 | 首版建议门槛 |
| --- | --- |
| 单张 32x24 纯数据生成 | 编辑器常规电脑上目标低于 20 ms |
| 生成加校验 | 目标低于 50 ms，最坏重试有总耗时上限 |
| 单关最大尝试次数 | 10 次，超过后立即 fallback |
| 批量 500 seed | 显示进度、可取消、不阻塞编辑器交互 |
| 可通行区域 | 最大连通分量覆盖全部可通行格的建议值不低于 90% |
| 公平模式双方最短路差 | 建议不超过 10%，具体按玩法测试调整 |

运行时不要在进入战斗后逐帧反复生成。地图应在加载阶段一次生成，完成后冻结为本局只读数据；视觉构建、单位生成和寻路查询全部读取同一份 `GeneratedMapData`。

## 17. 完善后的实施优先级

建议按以下优先级执行，避免工具先做得很完整但运行时接口仍不稳定：

1. 先确定 `BattleMapRequest / GeneratedMapData / GeneratedMapIdentity` 三个数据契约。
2. 完成纯算法、确定性 seed、版本号和 golden seed 测试。
3. 完成验证器，尤其是连续部署模板、真实寻路邻接规则和 fallback。
4. 完成编辑器预览、关卡范围配置、失败地图复现与批量验证。
5. 改造 `BattleStartContext`、`UnitSpawner` 和启动顺序，接入运行时。
6. 最后适配动态相机/小地图，并扩展建筑、道路和桥梁。

## 18. 结论

建议采用“先迁移纯算法，再做 Unity 编辑器测试工具，最后接入关卡号驱动”的路线。这样不仅能实现随机关卡地图，还能让你像演示项目一样快速调参、预览、批量验证，并配置“第几关到第几关使用哪套地图生成规则”。地图生成只产出格子、部署建议和关卡配置，单位归属、指挥官编队、移动攻击与胜负判定继续由现有战斗层负责。
