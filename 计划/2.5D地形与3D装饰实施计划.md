## 1. 目标与结论

本方案采用“2D 地面 + 3D 装饰”的 2.5D 表现方式：

- 保留现有 2D 地块作为连续、稳定的地图底层。
- 在森林、丘陵、山地、雪山、建筑、桥梁等格子上叠加 3D 模型。
- 随机地图、通行规则、寻路、部署、编队移动、攻击和撤离传送门规则不变。
- 3D 装饰只负责表现，不直接成为地图规则或鼠标点击依据。
- 任何 3D 装饰加载失败时，仍显示原有 2D 地形，战斗必须能够继续运行。

这一方案比完全 3D 化改动小、风险低，同时能显著改善当前“3D 单位站在平面贴图上”的割裂感。

### 开发前复查结论（重要）

本方案落地时必须额外遵守以下四项，否则会出现明显返工：

1. **装饰型地形不能继续使用带完整树木/山体图案的 2D Sprite 再叠加同类 3D 模型。**森林、丘陵、山地和雪山需要切换到“干净底图/弱化底图”，原完整 2D 图只作为 3D 资源缺失时的回退。
2. **3D 装饰不能成为 `BattleCellView` 旋转节点的子物体。**当前 2D Sprite 会随相机旋转；3D 装饰必须挂在独立、世界坐标朝上的根节点，否则树木、岩石和桥梁会整体倾斜。
3. **装饰生成必须晚于地图数据生成，但早于用户看见战场；排除数据直接读取 `GeneratedMapData`。**建筑、部署区和传送门位置已能从生成结果得到，不应等待场景对象注册后再二次修补。
4. **第一阶段不采用“每格一个装饰 MonoBehaviour”。**由一个地图级生成器管理所有装饰根节点，单个树木/岩石只保留 Transform、Renderer 等必要组件，降低对象和脚本开销。

## 2. 实施边界

### 本轮包含

- 导入并筛选 `Isometric Pack 3d v1.2` 中适合当前地图比例和风格的现成资源。
- 为现有十种 `TerrainType` 建立 3D 装饰映射。
- 森林、丘陵、山地、雪山、浅水边缘、道路边缘、桥梁和建筑的 3D 表现。
- 确保鼠标点击、框选语义、单位移动、攻击射线和传送门不被装饰模型干扰。
- 增加装饰密度、随机变体、确定性和性能控制。
- 保留完整的 2D 回退路径。

### 本轮不包含

- 不改变 `TerrainType` 和随机地图生成算法。
- 不引入真实高低层寻路、坡道或楼层玩法。
- 不让单位根据 3D 模型表面高度上下移动。
- 不修改指挥官编队命令规则；玩家仍然一次激活一名指挥官并整体下达命令。
- 不直接修改资源包中的 FBX 网格、UV、骨骼或动画。
- 不把 3D 装饰碰撞体作为通行判定来源。

如后续需要修改或制作正式 3D 网格、材质 UV、骨骼或动画，必须按照项目的 Blender MCP 工作规则另行实施。

## 3. 当前架构与目标架构

### 当前显示链

```text
BattleGridController.BuildVisual
  -> 每格创建 BattleCellView
  -> TerrainVisualCatalog 获取 2D Sprite
  -> SpriteRenderer 显示地面
```

### 目标显示链

```text
BattleGridController.BuildVisual
  -> 每格创建 BattleCellView
  -> 显示适合叠加装饰的 2D 底图
  -> TerrainDecorationCatalog 查询装饰规则
  -> 地图级 TerrainDecorationSpawner 实例化 0..N 个 3D 装饰
  -> 装饰统一进入不可拾取层，不参与地图规则
```

层级结构要求：

```text
BattleGrid
  GridVisual                 # 现有 2D Sprite 格子，可随相机旋转
  TerrainDecorationRoot      # 独立世界空间节点，rotation=(0,0,0)
    Forest
    Rocks
    Bridges
    SmallProps
```

`TerrainDecorationRoot` 不得挂到任一 `BattleCellView` 下。

逻辑层仍然只读取：

```text
TerrainType[,] + blocked/occupied cells + BuildingRegistry
```

不得从装饰 prefab、Renderer Bounds 或 Collider 反推通行规则。

## 5. 地形与装饰映射

| 地形 | 2D 底层 | 3D 装饰 | 初始密度 | 通行规则 |
| --- | --- | --- | ---: | --- |
| 平原 | 保留现有平原贴图 | 少量草、植物、小石块 | 0–1/格 | 不变 |
| 森林 | 使用林地色干净底图；原森林图仅作回退 | Tree1/2/4 系列，搭配小植物 | 1–3/格 | 不变 |
| 丘陵 | 使用土色/草色弱化底图；原丘陵图仅作回退 | 中小岩石、灌木 | 1–2/格 | 不变 |
| 山地 | 使用岩地色干净底图；原山地图仅作回退 | Rock_01..11 组合 | 1–3/格 | 不变 |
| 雪山 | 使用雪色干净底图；原雪山图仅作回退 | 岩石 + 雪色材质变体 | 1–3/格 | 不可走，保持现状 |
| 沙漠 | 保留沙漠贴图 | 沙色岩石、枯木或秋色植物 | 0–2/格 | 不变 |
| 浅水 | 保留浅水贴图 | 水草、岸边小石；中央不放高物体 | 0–1/格 | 不变 |
| 海洋 | 保留海洋贴图 | 第一阶段不叠加模型 | 0 | 不可走，保持现状 |
| 道路 | 保留道路连接贴图 | 路边石、路牌等低矮装饰 | 按边缘生成 | 不变 |
| 桥梁 | 保留桥梁贴图 | Bridge1/2 作为上层模型 | 1/桥格或桥段 | 不变 |

城市、兵工厂仍由建筑系统生成，不归普通地形装饰随机器管理，避免模型重复和占地冲突。

底图采用“双资源”策略：

```text
DecorationBaseSprite  # 启用 3D 装饰时使用，画面干净、只表达地表
FallbackFullSprite    # 3D prefab 缺失或关闭装饰时使用，保留现有完整地形图
```

如果某类地形尚未准备好干净底图，该类暂不启用 3D 叠加，不能接受双层山体作为临时完成结果。

## 6. 确定性与随机规则

3D 装饰必须与地图种子稳定绑定。同一个地图 seed、格子坐标和地形类型应生成完全相同的：

- prefab 变体；
- 数量；
- 格内偏移；
- Y 轴旋转；
- 允许范围内的缩放。

建议派生种子：

```text
decorationSeed = Hash(mapSeed, cellX, cellY, terrainType, decorationVersion)
```

禁止使用无状态的 `UnityEngine.Random` 影响战斗系统或导致同 seed 地图外观变化。装饰版本号变化时允许整体重新分布，但地图逻辑哈希不能变化。

## 7. 比例、位置与遮挡

- 当前逻辑格尺寸为 1×1 世界单位。
- 资源包 tile 预计约为 2×2 世界单位，第一阶段必须实测比例，装饰缩放统一由配置控制。
- 装饰根节点以格子中心为原点，局部偏移限制在格子安全范围内。
- 树木和山体底部必须贴近地面，不能悬空。
- 高模型不得覆盖指挥官头像、单位生命条和重要按钮。
- 树冠可遮挡单位时，后续可增加镜头前景淡化；第一阶段优先控制树高和偏移。
- 传送门占用范围内禁止生成高山、树木和建筑装饰；传送门周边至少保留一圈可读空间。
- 玩家与敌方部署区可降低装饰密度，防止出生单位被遮住。
- 2D Sprite 使用透明渲染队列、3D Mesh 使用深度缓冲，两者可能出现排序冲突；阶段 1 必须验证 3D 底部不会被前排 Sprite 错误盖住。
- 3D 装饰的 Renderer 默认接收阴影；只有山体和主要树木投射阴影，小植物与碎石关闭投射阴影以降低开销。
- 血条、指挥官头像、技能范围和选中标识继续使用独立高优先级渲染层，不能被 3D 深度遮挡。

## 8. 鼠标输入与物理隔离

所有 3D 装饰必须放入独立 Layer，例如：

```text
TerrainDecoration
```

要求：

- 玩家点击地面时仍解析逻辑格，不命中装饰模型。
- 单位选择、指挥官头像点击、攻击目标选择不受影响。
- 装饰 prefab 内已有 Collider 时，在生成时禁用或移除其运行时参与能力。
- 战斗 Raycast LayerMask 明确排除 `TerrainDecoration`。
- 装饰不写入 `BattleGridController.SetOccupied` 或 `SetBlocked`。
- 正式建筑继续通过现有建筑占格系统处理，不使用上述装饰规则。

当前地面点击主要通过 `BattleGridController.RayToGrid` 解析逻辑平面，因此不能为了点击装饰而改成“射线命中模型后取坐标”。3D 装饰即使没有 Collider，也必须完成移动、攻击、技能三条输入链的回归测试。

职责：

- `TerrainDecorationSpawner`：地图级管理器，根据地图 seed 和格子稳定生成、分组和清理装饰；不为每格创建脚本组件。
- `TerrainDecorationSetup`：建立 prefab variant、Layer 和配置资产；仅负责编辑器准备工作。

```text
Assets/Scripts/Battle/Map/BattleCellView.cs
```

`BattleCellView` 继续只负责 2D 地面，并根据装饰是否成功选择干净底图或完整回退图。3D 装饰由独立的地图级生成器管理，避免把贴图连接、装饰随机和建筑规则全部塞进一个类。

## 10. 性能策略

第一阶段目标支持 16×14 当前地图，并为更大地图预留余量：

- 普通格平均不超过 1.5 个装饰实例。
- 单格高密度森林上限 3 个主要模型。
- 禁用装饰碰撞体和无关脚本。
- 材质尽量共用，不为每个格子实例化材质。
- 优先选择 Mobile/低模版本；确认画质后再决定是否使用高模。
- 同 prefab、同材质启用 GPU Instancing（材质支持时）。
- 地图生成完成后装饰根节点保持静态，不在 `Update` 中运行逻辑。
- 第一阶段不做对象池；只有多次不切场景重建地图时再加入。
- 40×40 压力测试时记录帧率、Batches、SetPass Calls 和内存。

建议建立可量化预算：

| 地图 | 活跃 3D 装饰目标 | Draw Call 目标 | 生成耗时目标 |
| --- | ---: | ---: | ---: |
| 16×14 | ≤ 300 | ≤ 150 | ≤ 100 ms |
| 30×30 | ≤ 900 | ≤ 250 | ≤ 300 ms |
| 40×40 | ≤ 1500 | ≤ 350 | ≤ 500 ms |

以上为首轮桌面端预算，最终以 Unity Profiler 实测调整。性能报告必须区分“地图生成耗时”和“装饰实例化耗时”。

## 11. 分阶段实施

### 阶段 0：资源导入与风格门禁

1. 备份或记录导入前资源状态。
2. 完整导入 unitypackage，保持原目录结构。
3. 打开资源包 Demo 场景检查材质、光照和动画。
4. 在 Demo 或独立验证场景同时摆放步兵、坦克、火炮。
5. 实测树、岩石、桥梁与 1×1 战斗格的缩放。
6. 确认材质不发粉，视觉风格与现有单位基本协调。

验收：用户确认风格；记录基础缩放系数、推荐灯光和可用 prefab 清单。未通过则停止后续改造。

### 阶段 1：最小 2.5D 验证

1. 只接入森林、丘陵、山地三类装饰。
2. 为这三类准备干净底图，保留现有完整图作为 fallback。
3. 建立世界空间独立根节点、独立装饰层和确定性生成器。
4. 排除鼠标射线与碰撞影响。
5. 从生成数据预先建立建筑、部署区、道路和传送门排除格集合。
6. 测试地图和随机地图各验证一次。

验收：三类地形出现稳定 3D 装饰；相同 seed 外观一致；点击移动、攻击和编队选择与修改前一致。

### 阶段 2：十类地形与建筑协调

1. 补充平原、沙漠、雪山、浅水、道路、桥梁规则。
2. 海洋保持纯 2D，除非有明确低成本水面装饰。
3. 建立建筑、部署区、传送门范围的装饰排除规则。
4. 道路与桥梁根据连接 mask 处理朝向。
5. 调整各地形密度与随机变体。

验收：十种地形都有明确、统一的表现策略；无建筑穿插、桥梁错向、出生遮挡和传送门遮挡。

### 阶段 3：画面统一与性能

1. 调整主光、阴影强度、环境光和材质色调。
2. 对过高树木增加透明淡化或替换矮版本。
3. 开启可用的 GPU Instancing/静态批处理。
4. 在 16×14、30×30、40×40 地图上测试。
5. 根据性能结果建立低、中、高三档装饰密度。

验收：目标设备上运行稳定；无明显闪烁、穿插、粉色材质或大面积遮挡。

### 阶段 4：可选拓展

- 海岸线、瀑布、河岸过渡装饰。
- 不同季节或生态主题的装饰配置。
- 地图编辑工具中增加“3D 装饰预览”和密度滑杆。
- 战争残骸、路障、旗帜等不影响规则的主题装饰。
- 如需真实高度、坡道和楼层寻路，另立玩法与技术方案，不并入本阶段。

## 12. 验收用例

### 视觉

1. 森林格能看到树木，但仍能辨认底部格子。
2. 山地与雪山有不同色调和轮廓。
3. 桥梁方向与道路连接一致。
4. 建筑、单位、传送门与装饰不互相穿插。
5. 相邻格装饰不会形成规律性重复或明显越界。
6. 森林、丘陵和山地不存在 2D 图案与 3D 模型重复叠加。
7. 所有树木、岩石和桥梁保持世界 Y 轴朝上，不随 2D 地块旋转。

### 逻辑

1. 替换前后同 seed 地图的 `TerrainType` 和地图逻辑哈希一致。
2. 点击地面仍能得到正确格子。
3. 点击单位仍激活其所属指挥官编队，而不是装饰。
4. 移动、攻击、技能和阵型命令不绕过编队控制层。
5. 装饰不会改变可走、占用、阻挡和攻击范围计算。
6. 传送门范围内没有遮挡物，单位进入后能正确计入撤离。

### 稳定性与回退

1. 删除任意一个装饰 prefab 后，对应格仍显示 2D 地面且无异常。
2. 直接打开 `BattleScene` 能正常生成。
3. 从指挥官选择页面进入战斗能正常生成。
4. 随机地图工具“应用到 BattleScene 并运行”后装饰与当前 seed 一致。
5. Console 无 MissingReference、材质丢失或 Collider 干扰警告。
6. 关闭 3D 装饰总开关后，所有地形恢复现有完整 2D 表现。
7. 地图重建两次后不存在残留装饰、重复实例或静态缓存污染。

## 13. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 老资源材质在当前项目显示异常 | 阶段 0 先跑 Demo；异常时停止接入并记录材质迁移范围 |
| 3D 装饰挡住鼠标 | 独立 Layer、禁用 Collider、输入 LayerMask 排除三重保护 |
| 树木/山体遮住单位 | 控制高度与格内偏移，必要时做前景淡化 |
| 资源比例不统一 | 用单一配置记录每类 prefab 的缩放和底部偏移 |
| 随机装饰导致地图无法复现 | 使用局部确定性随机，不使用全局随机状态 |
| 大地图实例过多 | 限制密度、低模、共享材质、GPU Instancing、画质档位 |
| 建筑或传送门与装饰重叠 | 生成前读取排除格集合，先规则对象、后普通装饰 |
| 3D 与 2D 色调割裂 | 统一光照、阴影和材质色调，不修改地图规则解决美术问题 |

## 14. 完成定义

满足以下条件后，2.5D 地形阶段才算完成：

- 现有 2D 地面完整保留，缺失 3D 资源时可自动回退。
- 森林、丘陵、山地、雪山、沙漠、道路和桥梁具有合适的 3D 层次。
- 装饰生成与地图 seed 稳定绑定。
- 鼠标移动、攻击、技能、单位归属和指挥官编队命令不受影响。
- 建筑、部署区和传送门没有装饰穿插或遮挡。
- 随机地图逻辑哈希与替换前一致。
- 目标地图尺寸下性能符合要求，Console 无相关错误。
- 用户完成最终视觉验收。
