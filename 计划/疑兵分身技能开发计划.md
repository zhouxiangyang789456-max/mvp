# 疑兵分身技能开发计划

## 1. 技能定位

新增特殊技能“疑兵”。玩家点击技能后选择一个靠近当前指挥官编队的合法地图格，在该格生成一个短时存在的指挥官分身。分身会主动吸引附近敌方指挥官编队，使其暂时放弃原目标并移动过去攻击分身。

“疑兵”与现有“嘲讽”的区别：

| 技能 | 强制目标 | 主要用途 |
| --- | --- | --- |
| 嘲讽 | 施法者真实编队 | 把敌人集中到自己身边，配合坚守正面承伤 |
| 疑兵 | 放置在远处的临时分身 | 调离敌军、改变行军方向、制造绕行与空档 |

技能仍由当前激活的 `CommanderGroupRuntime` 释放，但分身不是新指挥官、不是新编队，也不允许玩家把它当成可控制单位。

## 2. MVP 推荐参数

| 参数 | 推荐值 | 说明 |
| --- | ---: | --- |
| 技能 ID | `skill_decoy` | 稳定逻辑 ID |
| 显示名称 | `疑兵` | 技能栏使用的名称 |
| 技能类型 | 特殊技能、地面目标 | 点击技能后选择落点 |
| 放置距离 | 4 格 | 以施法编队 `AnchorCell` 为中心，Chebyshev 距离 `<= 4` |
| 吸引半径 | 6 格 | 以分身落点为中心，命中范围内全部敌方编队 |
| 持续时间 | 8 秒 | 到期自动消失；被击破时提前结束 |
| 分身生命 | 80 | 接受正常伤害，但不受治疗和特性加成 |
| 冷却时间 | 18 秒 | 成功放置后立即进入冷却 |
| 同时存在上限 | 每个施法编队 1 个 | 再次成功放置时替换旧分身 |
| 视野 | 分身仅向被吸引敌军强制可见 | 不暴露施法者本体，不揭露敌军给玩家 |

首轮平衡优先调整“放置距离、持续时间、冷却”，不要用极高生命让敌人长期浪费攻击。

## 3. 操作流程

```text
点击“疑兵”
  -> 进入地面落点模式
  -> 显示指挥官周围 4 格合法范围
  -> 鼠标悬停显示半透明分身预览和 6 格吸引范围
  -> 点击合法格确认
  -> 创建分身
  -> 结算 6 格内敌方编队
  -> 敌方获得“强制攻击分身”状态
```

- 右键或 `Esc` 取消放置，不进入冷却。
- 切换指挥官、关闭指挥官面板或战斗冻结时取消未确认的预览。
- 成功放置后提示：“疑兵部署完成：吸引 N 支敌方编队”。
- 范围内没有敌人仍允许放置并进入冷却，因为敌军可以在分身存续期间进入吸引范围。为避免每帧扫描，分身按 `MediumTick`（0.1 秒）检查新进入范围的敌方编队。

## 4. 落点合法性

分身落点必须同时满足：

1. 战斗阶段，当前玩家编队存在且未失败。
2. 与施法编队锚点的 Chebyshev 距离不超过 4 格。
3. 地图内、可行走、不是水面或永久障碍。
4. 当前没有单位、建筑、其他分身或编队目标槽位占用。
5. 不在其他编队已提交的阵型预留格内。

不要求落点附近存在敌人。非法落点使用红色预览并显示具体原因：“超出施放范围 / 目标格不可用 / 目标格已被占用”。

## 5. 分身运行时模型

分身必须使用独立运行时数据，禁止创建假的 `CommanderGroupRuntime`：

```csharp
TacticalDecoyRuntime
{
    string DecoyId;              // decoy_{sourceGroupId}_{sequence}
    string SourceGroupId;
    TeamId Team;
    Vector2Int Cell;
    int CurrentHealth;
    int MaxHealth;
    float SpawnedAt;
    float ExpiresAt;
    long SkillSequence;
    DecoyView View;
    bool Destroyed;
}
```

建立 `TacticalDecoyRegistry`，负责：

- `DecoyId -> TacticalDecoyRuntime` 唯一映射。
- 查询某格是否有分身。
- 施法编队到当前分身的映射。
- 创建、替换、受伤、击破、到期与场景清理。
- 分身格的临时占用和释放。

分身不得加入：

- `CommanderGroupRegistry.Groups`
- 施法编队 `Members`
- `UnitSelectionController` 的友军选择语义
- 单位卡、编队生命、部署槽位、胜负统计和可占领单位数量

## 6. 攻击目标接入方案

当前 `CommanderGroupCommandController.CommandAttack` 和 `UnitCombatController` 以 `UnitView` 为攻击目标。MVP 推荐使用“攻击代理”接入，而不是重写整个战斗目标系统：

1. `DecoyView` 提供一个只用于受击的攻击代理。
2. 攻击代理携带 `IsTacticalDecoy = true` 和 `DecoyId`，但 `CommanderGroupId` 为空。
3. 它不注册为普通玩家单位，不参与编队查找。
4. 敌军编队攻击时 `TargetGroup == null`，只锁定该分身代理。
5. 所有敌军成员保持阵型移动到分身周围的合法战斗锚点，然后攻击同一个分身。
6. 分身生命归零时，攻击计划统一结束，不允许因为 `TargetGroup == null` 自动改打施法者本体。

需要给攻击代码增加明确的战术目标分支，禁止依赖“找不到目标编队就碰巧工作”。至少新增：

```csharp
GroupCommandType.AttackTacticalTarget
string TargetTacticalId
```

这样日志、命令序号、失败收敛和后续其他诱饵类技能都有稳定入口。

## 7. 吸引与敌军 AI 规则

### 7.1 命中判定

- 距离以敌方编队 `AnchorCell` 到分身 `Cell` 计算。
- 使用 Chebyshev 距离，`distance <= 6` 时命中。
- 只影响 `TeamId.Enemy`、未 `Defeated` 的完整敌方编队。
- 一个敌方编队只保存一个强制目标状态，不按成员重复。

### 7.2 强制行为

命中后敌方：

1. 立即从 `Dormant`、调查、恢复或普通交战状态转入强制响应。
2. 取消普通攻击和最后已知位置调查。
3. 发出 `AttackTacticalTarget`，围绕分身格寻找完整合法战斗锚点。
4. 持续期间不能因更近的真实玩家编队而改选目标。
5. 寻路失败时短暂重试；连续失败后原地等待，不得转攻无关目标。

### 7.3 新进入范围的敌军

分身存续期间每个 `MediumTick` 检查尚未命中的敌方编队。新进入 6 格范围的敌军也会被吸引；已经离开 6 格范围的敌军不会立即解除，仍持续攻击分身直到分身消失或被击破，避免边界抖动。

## 8. 与现有嘲讽的优先级

将现有 `TauntEffectService` 的“强制目标”概念抽成通用 `ForcedAggroService`：

```csharp
ForcedAggroState
{
    string AffectedGroupId;
    ForcedTargetKind TargetKind; // CommanderGroup / TacticalDecoy
    string TargetId;
    float ExpiresAt;
    long AppliedSequence;
}
```

规则采用“后成功施加者覆盖先施加者”：

- 先嘲讽本体、后生成疑兵：敌人改攻疑兵。
- 先攻击疑兵、后使用本体嘲讽：敌人改攻本体。
- 同一分身重复扫描已受影响敌军时不刷新、不产生重复命令。
- 分身消失后只移除以该 `DecoyId` 为目标的强制状态，不能误删后来覆盖的本体嘲讽。

这个统一层可以避免敌军 AI 同时维护两套互相冲突的强制目标判断。

## 9. 视野、隐蔽与战争迷雾

- 分身对吸引范围内敌军强制可见，即使它们原本看不到落点。
- 强制视野对象是分身，不是施法编队；施法者本体不会因释放“疑兵”而暴露。
- 释放疑兵不会解除施法者的“隐蔽”，但进入瞄准和确认时不能同时进行其他技能操作。
- 疑兵不会向玩家揭露战争迷雾中的敌人；玩家只看到技能命中数量。
- 分身视野到期、被击破或被替换时必须立即移除，不能等下一轮普通视野刷新。
- 敌人攻击分身期间若自然发现真实玩家编队，仍因强制目标优先级继续攻击分身。

## 10. 分身视觉与交互

MVP 不新增或修改 3D 模型：

- 优先复用当前指挥官头像或已有指挥官表现，创建半透明蓝白色分身。
- 没有指挥官世界模型时，使用世界空间头像、底部光圈和轻微脉冲表达“分身”。
- 分身头顶显示短生命条或剩余时间环。
- 当前玩家鼠标不能选中或控制分身；点击分身所在格不改变当前激活指挥官。
- 敌军可以正常以其为攻击目标。
- 到期播放淡出，被击破播放短促破碎/消散效果，然后释放对象。

如果后续需要实质制作新的3D分身模型、网格或动画，必须另行按 Blender MCP 规则制作；首轮仅复用已有视觉，不触发3D资产制作。

## 11. 冷却、替换和失败规则

- 成功创建分身后立即开始18秒冷却。
- 取消瞄准或非法落点不进入冷却。
- 每个施法编队最多存在一个分身。
- 同一编队下一次成功放置时，先安全销毁旧分身，再创建新分身；旧分身吸引状态只在新分身成功创建后清理，避免失败放置误删旧分身。
- 施法编队失败不会立刻销毁已存在分身；分身继续存在到自身到期或被击破。
- 战斗结算、场景退出和服务关闭时清理所有分身、强制目标、视野、格子占用和对象池实例。
- 分身不计入任何一方失败判定，也不给击破者经验、金币或占领贡献。

## 12. UI 与技能栏

- 技能栏增加“疑兵”。
- Tooltip：`4格内放置分身，吸引分身周围6格敌军，持续8秒；冷却18秒。`
- 点击后使用现有 `SkillTargetingController` 与 `SkillRangePreview`，但目标验证委托给技能自己的放置规则，不能硬编码为“远攻”。
- 预览至少包含：4格施放范围、当前落点分身虚影、6格吸引范围、非法格红色反馈。
- 确认后显示命中编队数；分身被击破或到期可显示简短状态提示。

为支持不同地面技能，建议把当前 `SkillTargetingController` 拆成按 `SkillId` 分派的确认策略：

```csharp
ISkillTargetingHandler
{
    bool ValidateCell(...);
    bool ConfirmCell(...);
    void Cancel(...);
}
```

“远攻”和“疑兵”分别实现自己的处理器，避免继续在一个方法中堆积技能判断。

## 14. 自动化测试

至少覆盖以下测试：

1. 4格内落点合法，5格外非法。
2. 对角 `(4,4)` 按 Chebyshev 距离合法。
3. 水面、障碍、建筑、单位占用、阵型预留格不可放置。
4. 取消瞄准不进入冷却。
5. 成功放置后冷却18秒。
6. 分身8秒到期并释放格子占用。
7. 分身80生命归零时提前消失。
8. 6格内敌方编队被吸引，7格外不受影响。
9. 一个敌方编队多个成员只命中一次。
10. 新进入6格范围的敌方在下一次扫描被吸引。
11. 已命中敌方离开6格后仍保持目标直到分身消失。
12. 敌人以分身为目标时不会把施法者本体作为 `TargetGroupId`。
13. 分身消失后敌军强制目标清除并恢复普通AI。
14. 后施放的本体嘲讽覆盖疑兵目标。
15. 后生成的疑兵覆盖本体嘲讽目标。
16. 同来源重复扫描不重复发命令或刷新状态。
17. 替换旧分身只清理旧 `DecoyId` 的状态。
18. 释放疑兵不会解除施法者隐蔽或暴露本体。
19. 未被吸引的敌军不会获得分身强制视野。
20. 分身不进入编队成员、单位卡、胜负和奖励统计。
21. 战斗结算和场景退出后无分身对象、视野、占用或强制目标残留。

## 15. 手工验收流程

1. 在玩家指挥官4格内放置分身，确认预览、落点和吸引范围正确。
2. 放置两支6格内敌军和一支7格外敌军，确认只有前两支转向分身。
3. 观察敌军保持完整阵型移动到分身附近并攻击分身，不攻击玩家本体。
4. 让一支敌军后来进入6格，确认它也被吸引。
5. 测试分身被击破和8秒自然到期，两种情况都能立即解除强制目标。
6. 依次测试“嘲讽→疑兵”和“疑兵→嘲讽”，确认最后成功施加的技能生效。
7. 在施法者隐蔽时释放疑兵，确认本体仍保持隐蔽且未被定向暴露。
8. 快速连续点击、取消、非法落点和切换指挥官，确认不会误扣冷却或留下预览。
9. 检查单位卡、胜负、奖励、占领和日志，确认分身没有被当成普通单位。

## 16. 开发顺序

1. 先建立 `TacticalDecoyRuntime`、注册表、落点规则、生命和到期清理，并完成纯数据测试。
2. 将现有嘲讽强制目标抽为 `ForcedAggroService`，保持现有嘲讽测试全部通过。
3. 增加敌军对战术目标的编队攻击命令，完成分身死亡后的攻击收敛。
4. 接入地面技能瞄准、双范围预览、技能栏与冷却。
5. 接入定向视野、隐蔽隔离、对象池视觉和完整生命周期。
6. 编译运行时与编辑器测试程序集，运行EditMode测试并进行战斗场景手工验收。

## 17. 首轮平衡观察项

试玩时记录：平均吸引编队数、敌军到达分身所需时间、分身平均存活时间、成功调离距离以及与本体嘲讽/坚守组合的收益。如果过强，优先把持续时间从8秒降到6秒或冷却从18秒提高到22秒；如果敌军经常尚未靠近分身就消失，优先把生命从80提高到100，而不是盲目延长持续时间。
