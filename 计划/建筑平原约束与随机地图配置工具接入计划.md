# 建筑平原约束与随机地图配置工具接入计划

## 1. 目标

本次改造解决两个问题：

1. 楼房与兵工厂所属的全部地形格必须是平原，不能再与森林、沙滩、道路、水域或其他地形组合。
2. 将楼房与兵工厂作为明确的建筑类型接入“随机地图配置工具”，允许策划分别配置数量、预览结果并保存到关卡地图配置。

本阶段只调整建筑生成、配置、校验和预览，不改变建筑占领、产金、生产、寻路及指挥官编队玩法。

## 2. 当前问题确认

### 2.1 建筑逻辑占地与目标规则不一致

- `BuildingCatalog` 中楼房与兵工厂的 `Footprint` 均为 `2×2`。
- `ProceduralMapGenerator` 当前用 `GeneratedBuilding[,]` 把建筑记录成单格标记。
- `ProceduralBattleMapProvider.StoreBuildings()` 当前只把建筑锚点格转换为 `Plain`。
- 因此建筑另外三个占地格可能仍是森林、沙滩或道路，画面上就会出现建筑与非平原地形拼接。

### 2.2 生成条件过宽

- 当前 `IsBuildable()` 接受 `Plain / Beach / Road`。
- 这不符合“建筑所属地形只能是平原”的新规则。
- 道路连接还可能在建筑生成后改变建筑附近或建筑锚点的地形，需要额外保护建筑占地区域。

### 2.3 运行时缺少最终防线

- `BuildingRegistry.RegisterBuilding()` 当前只检查格子可通行、未被占用。
- 森林等可通行地形仍可能通过检查。
- 即使未来出现手工配置、旧存档或其他生成入口，也可能再次把建筑放到非平原格。

### 2.4 配置工具名称仍是旧概念

- 随机地图工具目前显示“工厂数”和“城市数”。
- 运行时实际映射为：`City → 楼房`，`Hq / Factory → 兵工厂`。
- 工具没有直接展示两个正式建筑类型，也没有验证建筑所在单格是否为平原。

## 3. 统一规则

### 3.1 地形规则

- 楼房：只占 1 个格子，该格必须为 `TerrainType.Plain`。
- 兵工厂：只占 1 个格子，该格必须为 `TerrainType.Plain`。
- 建筑所在格不得是森林、丘陵、山地、雪山、沙漠、浅水、海洋、沙滩、河流、桥梁或道路。
- 建筑相邻格可以是其他地形或道路，但道路不得覆盖建筑所在格。

### 3.2 数据规则

- 随机地图配置直接使用“楼房数量”和“兵工厂数量”。
- 生成结果继续保存稳定 seed；相同 seed 与相同配置必须得到相同建筑类型和位置。
- 每栋建筑是一个运行时对象，只占据并阻挡一个格子。
- 生成数量无法满足时不得偷偷放到非平原，应返回实际生成数量并在工具中显示警告。

## 4. 实施方案

### 阶段一：统一建筑类型配置

修改 `MapGenerationSettings`：

- 用清晰字段表达 `HouseCount` 与 `ArmoryCount`。
- 对已有 `Cities / Factories` 配置做兼容迁移，避免现有关卡配置丢失。
- 明确 HQ 是否继续参与地图逻辑；若 HQ 没有独立建筑资源，则不再额外映射成兵工厂，避免兵工厂数量与工具配置不一致。
- 所有数量限制为非负数，并设置符合地图尺寸的合理上限。

建议最终规则：

| 工具配置 | 生成数据 | 运行时建筑 |
| --- | --- | --- |
| 楼房数量 | `GeneratedBuilding.City` 或新 `House` 枚举 | `building_house` |
| 兵工厂数量 | `GeneratedBuilding.Factory` 或新 `Armory` 枚举 | `building_armory` |

优先建议把生成枚举同步改为 `House / Armory`，消除 City、Factory、HQ 与正式玩法名称之间的长期歧义。

### 阶段二：按单格平原规则选择位置

修改 `ProceduralMapGenerator`：

- 将楼房与兵工厂在 `BuildingCatalog` 中的 `Footprint` 统一改为 `1×1`。
- 建筑候选格在放置前必须严格等于 `GeneratedTerrain.Plain`，不再接受 Beach 或 Road。

- 检查边界、建筑间距、部署区、已有建筑重叠和道路保护。
- 对称地图先在半图寻找合法的平原格，再镜像建筑位置；镜像后再次验证两侧均为平原。
- 道路寻路把建筑所在格加入禁铺集合，只允许道路连接到建筑外围相邻格。

### 阶段三：生成数据转换时固化平原

修改 `ProceduralBattleMapProvider.StoreBuildings()`：

- 每个建筑标记对应一个正式建筑和一个地形格。
- 将建筑所在格统一转换为 `GeneratedTerrain.Plain`。
- 转换前检查是否越界；非法数据跳过并记录包含 seed、建筑类型和坐标的警告。
- 生成 `BuildingSpawnData` 后，对每栋建筑执行“所在格必须为平原”的断言或验证。

这里作为数据转换层的修复，可以兼容旧版随机地图数据。

### 阶段四：运行时注册增加硬校验

修改 `BuildingRegistry.RegisterBuilding()`：

- 除现有的边界、占用和可通行检查外，验证建筑所在格必须严格等于 `TerrainType.Plain`。
- 校验失败时不注册建筑，并输出建筑 ID、锚点和失败格坐标。
- 默认测试地图的五个固定建筑也必须通过相同规则，不设置绕过路径。

这一层是最终防线，防止手工地图、旧数据或未来的新入口生成非法建筑。

### 阶段五：随机地图配置工具接入两个建筑

修改 `RandomMapToolWindow`：

- “生成建筑”开启后显示：
  - `楼房数量`
  - `兵工厂数量`
- 删除或迁移用户可见的“城市数”“工厂数”旧命名。
- 在地图预览中使用楼房、兵工厂两种不同图标或缩略图；若正式 Sprite 不适合编辑器预览，可先使用清晰的不同色标记并标注图例。
- 统计区分别显示“计划数量 / 实际数量”。
- 增加校验结果：
  - 非平原建筑格数量必须为 0。
  - 建筑越界数必须为 0。
  - 建筑重叠数必须为 0。
  - 实际数量不足时显示黄色警告。
- 保存配置、载入配置、预设和“应用到 BattleScene”都必须包含两个建筑数量字段。

### 阶段六：测试与验收

新增或扩展编辑器测试：

1. 自由地图：批量 seed 生成后，每栋建筑所在单格均为平原。
2. 对称地图：建筑位置与类型保持 180° 对称，且两侧建筑格均为平原。
3. 小地图或平原不足：建筑数量可以不足，但绝不落到其他地形。
4. 道路生成：道路不覆盖建筑所在格。
5. 转换兼容：旧建筑标记转换后，建筑所在格被规范为平原。
6. 运行时防线：尝试在森林格注册楼房或兵工厂必须失败。
7. 工具持久化：保存并重新加载配置后，楼房与兵工厂数量不变。
8. 可复现性：相同 seed、尺寸和配置得到相同地图哈希、建筑类型及坐标。
9. 编译：`Assembly-CSharp.csproj` 与编辑器程序集均无新增错误。

## 5. 推荐开发顺序

1. 先补测试，复现“建筑定义为 2×2 且允许落在非平原格”的问题。
2. 修改建筑候选位置与道路保护逻辑。
3. 修改生成数据转换，保证建筑所在格转为平原。
4. 给 `BuildingRegistry` 增加严格平原校验。
5. 迁移配置字段和生成建筑枚举命名。
6. 更新随机地图配置工具的字段、预览、图例和统计。
7. 批量 seed 测试、编译验证，并在 Unity 编辑器中人工检查预览与战斗场景。

## 6. 验收标准

- 任意随机 seed 下，楼房和兵工厂都只占一个格子，且该格为平原。
- 建筑不会与森林、沙滩、道路、水域等地形拼接。
- 随机地图配置工具可分别设置楼房与兵工厂数量。
- 预览可清楚区分两种建筑，并显示计划数量与实际数量。
- 平原不足时给出明确提示，不降低规则把建筑塞到其他地形。
- 配置保存、关卡读取、地图复现和运行时生成链路保持一致。
- 不影响建筑占领、楼房产金、兵工厂生产、单位寻路和指挥官编队控制。

## 8. 风险与处理

- **旧配置字段迁移**：保留序列化兼容或提供一次性迁移，防止现有关卡建筑数量归零。
- **平原候选格不足**：扩大候选次数并报告实际数量，不放宽平原规则。
- **对称地图偶数/奇数尺寸差异**：镜像后重新校验建筑所在格与边界。
- **道路与建筑冲突**：道路规划显式避开建筑所在格，而不是生成后覆盖回来。
- **默认测试地图失效**：开发前先核对每个固定建筑坐标；非法时迁移到最近的平原格。
