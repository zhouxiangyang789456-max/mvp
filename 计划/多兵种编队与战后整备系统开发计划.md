# 多兵种编队与战后整备系统开发计划

## 1. 目标与范围

本计划承接当前“多指挥官出征、战斗中一次激活一名指挥官、整编队执行玩家命令”的基础规则，扩展为：

- 每名指挥官初始拥有一个与其兵种分支一致的强化单位。
- 陆军指挥官分为步兵、机械、远程三个兵种分支。
- 战后用金币购买装备、军事单位和卡牌。
- 下一战前进入队伍调整页，将库存分配给不同指挥官。
- 兵种技能与兵种稳定 ID/标签强绑定；增加同兵种单位可扩大技能参与数量或提高技能效果。
- 鼠标点击移动、攻击和技能均具备对应单位动画、选中标识和命令反馈。

本轮仅完成三个初始强化单位的资源替换与基础动画接线；商店、升级、队伍调整和完整兵种技能后续分阶段开发。

## 2. 初始指挥官与强化单位

| 指挥官 | 分支 | 初始单位类型 | 美术资源 | 初始格数 |
| --- | --- | --- | --- | ---: |
| 伊莲娜 | 步兵 | Infantry | `SimpleMilitary_SpecialForces01_Black` | 1 |
| 卡西安 | 机械 | Tank | `SK_Veh_Tank_01` | 1 |
| 薇拉 | 远程 | RocketArtillery（暂用现有稳定类型） | `SK_Veh_FieldGun_01` | 1 |

初始单位在数值上属于对应指挥官的强化单位，但本轮不重做数值成长；强化数值、升级曲线和稀有度在兵种成长阶段统一配置。

步兵的一格仍可显示多名士兵组成的小队，但运行时只占一个阵型槽、拥有一个单位 ID 和一份战斗状态，不允许把视觉成员分别控制。

## 3. 多兵种编队数据模型

### 3.1 稳定身份

后续将现有 `UnitType` 作为战斗原型 ID，并增加独立的兵种成长定义：

```text
UnitArchetypeId       // 兵种稳定 ID
UnitType              // 现有战斗原型
TroopBranch           // Infantry / Mechanical / Ranged
UnitTags              // Infantry、Tank、Ranged、CanCaptureBuilding 等
SkillIds              // 该兵种拥有的技能
UpgradeLevel          // 兵种技能/数值等级
VisualPrefabId        // 美术资源 ID
AnimationProfileId    // 动画映射 ID
```

购买和存档保存稳定 ID、数量、等级与所属指挥官，不保存场景对象或 `MonoBehaviour`。

### 3.2 指挥官战前编组

每名出征指挥官拥有独立的战前配置：

```text
CommanderId
AssignedUnitStacks
AssignedEquipment
AssignedRelics
AssignedCards
FormationLayout
```

同一个库存实例只能分配给一名指挥官；点击确认时一次性校验并生成下一场战斗快照。

## 4. 移动规则

### 4.1 速度规则

编队移动速度取所有参与移动且存活成员的最小 `MoveSpeed`。快速成员不得脱离阵型独自先行。

原因：

- 能维持编队锁定槽位和视觉整体性。
- 玩家可以预测整队到达时间。
- 避免远程或步兵被坦克等不同速度单位拉散。
- 与当前编队规则中的速度上限机制一致。

### 4.2 三档兵种速度

UI和编组提示按三类展示，不强制禁止混编：

| 档位 | 分支 | 典型特征 |
| --- | --- | --- |
| 步兵 | Infantry | 中速、可占领、适合城市和复杂地形 |
| 机械 | Mechanical | 较快或重型较慢、耐久高、受地形约束 |
| 远程 | Ranged | 通常最慢、需要阵地和最小射程保护 |

当编队混入更慢档位时，在队伍调整页显示“编队速度将降低至 X”的即时提示，以正向鼓励同类兵种编组。

### 4.3 移动动画

- 步兵：使用无 Root Motion 的 `Walk_Static`/`Run_Static`，实际位移由格子寻路控制。
- 轮式车辆：根据实际速度驱动车轮滚动。
- 坦克：本轮支持车体移动、炮塔瞄准和开火后坐；履带滚动待 Blender 分离履带网格后实现。
- 野战炮：根据实际速度驱动车轮；战斗中保持整件火炮作为一个单位移动。

## 5. 攻击规则

### 5.1 编队停止条件

玩家点击敌方编队后，系统计算一个能够保持当前阵型快照、同时让编队中最大攻击射程成员覆盖目标的战斗锚点。

- 目标进入编队最大射程后，整编队锚点停止。
- 实际射程覆盖目标的成员执行攻击。
- 射程不足的成员保持自己的锁定槽位，不独立追击、不跨槽位挤向敌人。
- 如果目标移动导致所有成员都失去射程，只允许整体更新战斗锚点。
- 如果完整阵型没有合法战斗锚点，攻击命令整体失败并提示“阵型受阻”。

该规则保留远程兵种的距离优势，同时避免“全员必须进入各自射程”导致远程单位被迫贴脸，也避免成员各自追击造成编队失控。

### 5.2 目标分配

- 首选玩家点击的 `PrimaryTargetUnitId`。
- 主目标死亡后，只在同一个 `TargetGroupId` 内重新选择。
- 每名成员根据自身射程、冷却和武器类型决定是否开火。
- 目标编队失败后统一结束攻击，不自动跨编队追击。

### 5.3 攻击动画同步

攻击动作必须在实际伤害/投射物产生时触发，而不是仅在进入 `Attacking` 状态时播放一次。

- 步兵：按武器映射到手枪、自动步枪、冲锋枪、霰弹枪、步枪或 RPG 动作。
- 坦克/火炮：炮塔或炮管持续瞄准；每次开火触发炮管后坐和复位。
- 枪口火焰、弹道和命中特效与同一次开火事件同步。

## 6. 兵种技能规则

### 6.1 强绑定

每个兵种技能定义必须声明：

```text
SkillId
RequiredUnitType 或 RequiredUnitTags
TargetingMode
EligibleMemberPolicy
AnimationCue
HighlightStyle
UpgradeScaling
```

技能资格由兵种/标签决定，不靠单位显示名称或 Prefab 名称判断。

### 6.2 技能子集选择

兵种技能允许从当前指挥官编队中选择符合条件的单位子集，但它属于技能命令层，不恢复普通单兵控制：

1. 点击技能按钮。
2. 系统筛出符合兵种条件且可用的成员。
3. 符合条件的单位显示统一兵种颜色、描边或地面环；其他成员降亮度。
4. 玩家点击合法目标或地面。
5. 只有符合条件的技能子集执行技能，其余成员保持原槽位和原命令。
6. 技能完成、取消、切换指挥官或目标失效时清除全部标识。

### 6.3 占领示例

“步兵占领城市”要求 `CanCaptureBuilding`：

- 激活技能后，高亮当前编队内所有可占领步兵。
- 玩家点击城市后，从可用步兵中按距离、存活状态和路径选择执行者。
- 被选执行者显示更强的确认色并前往城市。
- 其他单位不移动，编队槽位保留为空缺。
- 占领结束或中断后，执行者按统一的 `Regroup` 命令返回原槽位。

如果技能设计要求多名步兵共同参与，则参与数量由技能等级和同兵种数量决定，但必须在技能开始时一次性锁定参与者。

### 6.4 兵种升级含义

增加兵种或升级兵种技能可以提升：

- 可参与技能的单位数量。
- 技能数值、范围、持续时间或冷却。
- 高等级动作、特效和标识层级。
- 单位数值与装备槽，但不改变普通点击仍为编队整体命令的原则。

## 7. 战后商店与队伍调整流程

```text
战斗结算
  -> 获得金币/战利品
  -> 商店：装备 / 部队 / 卡牌
  -> 指挥官升级页
  -> 队伍调整页
  -> 生成下一战配置快照
  -> 下一场战斗
```

### 7.1 商店页

参考用户提供的第一张线框图：

- 顶部显示金币，并提供部队、卡牌分类切换。
- 左侧展示已拥有装备与遗物。
- 中部和右侧展示可购买商品卡。
- 底部提供锁定、刷新和确认。
- 购买士兵阶段可复用同一商店布局，只替换商品类型和详情字段。

### 7.2 指挥官升级页

参考第二张线框图与第三张参考图：

- 中央为指挥官立绘、名称、生命和特性说明。
- 底部为多个可升级模块或技能节点。
- 左右切换指挥官或升级分支。
- 升级结果写入持久化指挥官成长数据，不直接修改战斗场景对象。

### 7.3 队伍调整页

参考第四张线框图和第五至七张参考图：

- 左侧为出征指挥官列表。
- 中左侧切换部队、装备、遗物、卡牌页签。
- 中央/右侧显示当前指挥官模型、详情和已装备内容。
- 支持库存筛选、等级排序、分支筛选和替换。
- 点击确认前检查重复分配、容量、兵种限制和至少一个初始单位。

## 8. 分阶段开发

### 阶段 A：初始强化单位资源替换（本轮）

- 伊莲娜初始单位改为一格 SpecialForces01 步兵。
- 卡西安初始单位使用 Tank 01。
- 薇拉初始单位使用 FieldGun 01。
- 建立模型 Profile，保存缩放、朝向、单格视觉数量和动画类型。
- 接入步兵待机/移动/开火与车辆移动部件、瞄准、后坐动画。
- 编译并验证 Prefab、Animator、材质、动画组件和三名指挥官初始数量。

### 阶段 B：兵种与库存数据

- 建立兵种原型、库存实例、装备、遗物、卡牌和成长存档。
- 建立战后奖励和商店购买事务。
- 保证购买、刷新和锁定可存档、可回滚。

### 阶段 C：队伍调整页

- 实现指挥官列表、库存分类、装备/部队/卡牌分配。
- 生成只读战前编组快照。
- 加入兵种档位和编队速度预览。

### 阶段 D：多兵种编队移动与攻击

- 编队速度使用存活移动成员最小值。
- 计算最大射程战斗锚点。
- 射程不足成员留槽，射程内成员攻击。
- 完成混编、目标移动、不可达和成员死亡测试。

### 阶段 E：兵种技能选择与标识

- 建立兵种技能资格筛选和高亮生命周期。
- 首先实现步兵占领城市。
- 再接入机械和远程专属技能。
- 完成取消、切换指挥官、目标失效和技能结束后的重整。

### 阶段 F：商店与升级 UI 美术化

- 按用户线框和参考图完善商店、指挥官升级和队伍调整视觉。
- 统一卡牌、品质、价格、锁定、替换和详情交互。
- 完成 1600×900 基准分辨率和常见宽高比适配。

## 9. 验收原则

- 每名指挥官初始恰好拥有一个配置单位格。
- 三种初始单位均使用指定资源，且没有丢失材质或脚本。
- 鼠标移动、攻击与技能事件能够驱动对应动画，不使用 Root Motion 改变逻辑位置。
- 普通输入始终作用于当前指挥官编队；兵种子集只在技能上下文中临时成立。
- 混合编队移动时快速成员不脱队。
- 攻击时编队在最大射程锚点停下，成员不独立追击。
- 商店购买与队伍调整只修改持久化配置和战前快照，不直接修改战斗场景对象。
