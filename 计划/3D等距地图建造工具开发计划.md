# 3D 等距地图建造工具开发计划

## 1. 目标与背景

用户已把 `Isometric Pack 3d v1.2` 完整导入 `Assets/Isometric Pack 3d/`（497 个 prefab，含 30+ 树、11 岩石、6 水、2 桥、8 坡、5 楼梯、20+ 植物、8 蘑菇、4 banner、围栏/营火/宝箱等）。Demo 场景（`Demo/Scene1`、`Demo/Scene2`）观感良好，用户希望**手动手工拼一张 3D 等距地图**，而不是靠 `ProceduralBattleMapProvider` 程序化生成。

目标：**做一个 Unity EditorWindow 工具**，上方实时 3D 等距预览，下方是**可翻页的 prefab 调色板**，点击 prefab 后再点地图格子放置；保存后可作为关卡地图加载进 BattleScene。

参考原型（用户给的 UI 草图）：
- 上方 70% 是地图预览（透视/等距相机）
- 下方一排约 8 个方格，预览图缩略图，最左侧是"地形块"（基础地形），右滑/翻页可切换到"装饰""建筑""水""桥""Props"等类别
- 用户建议"在地形栏上下做两个按钮或者其他东西，表示可以到别的地形类别"

## 2. 与现有体系的关系

| 现有 | 关系 |
| --- | --- |
| `TerrainType` 枚举（10 种） | **作为放置分类的中介**：每个 prefab 标注一个或多个 TerrainType 标签，工具调色板按 TerrainType 分页 |
| `BattleCellView` | **不直接改**——工具造出的"地图数据"通过 `GeneratedMapData` 序列化喂给现有 `ProceduralBattleMapProvider` 路径，运行时仍走 `BattleCellView`（仍渲染 2D 贴图，**这意味着运行时视觉与编辑器视觉不一致**——属于已知妥协，详见 §7） |
| `LevelMapGenerationProfile` + `Rule` | **新模式：手工地图**——profile 里加一个 `HandAuthoredMapData` 字段，引用一份手工地图资产，优先级高于程序化生成 |
| `RandomMapToolWindow` | **不是它**——这是程序化地图工具，新建独立工具 `HandMapBuilderWindow`，但可放在 `Tools/Map Generation/Hand Map Builder` 同一菜单下 |
| `PortalPlacementPlanner` 等放置算法 | 不动；手工地图自带 anchor，传送门锚点直接由用户在地图上画 |

### 3.2 调色板"分类"

按用户诉求"在地形栏上下做两个按钮或者其他东西，表示可以到别的地形类别"——按**功能类别**分页，而不是按材质：

| 类别 ID | 显示名 | 内容（prefab 示例） | 对应 TerrainType 标签 |
| --- | --- | --- | --- |
| `Base` | 基础地形 | Tile_1_A..H（边角件）、Tile_Grass1-5（草地块）、Tile_1_brick_A..H（砖地，可作路） | Plain |
| `Forest` | 森林 | Tree1_1..1_5、Tree2_1..2_8、Tree3_01..07、Tree4_01..05、Plants_03~17、Tree1_1b..Tree1_5b | Forest |
| `Hill` | 山丘 | Rock_01..11（小石）、Tile_Ramp1A-2B（坡道） | Hill |
| `Mountain` | 山地 | Rock_01..11（大石组合）、Stairs_1-2、Stairs_Debris1-3 | Mountain |
| `Water` | 水系 | Tile_Water1A-D、Tile_Water2、Water1、Waterfall1-2 | ShallowWater / Ocean |
| `Bridge` | 桥梁 | Bridge1、Bridge2 | Bridge |
| `Road` | 道路（合成） | Tile_1_brick_A..H + A-H 自动按邻居掩码选边 | Road |
| `Building` | 建筑 | Camp1 系列（Barricade/Brick/Shield/Tower）、Magic_Shrine、Mine 系列 | 内部标记为 Building |
| `Decoration` | 装饰 | Banner_Pole1-4、Barrier1、Fence1_1~3、Lamp_01、Mushroom1A-4B、Glow1、Well1、Plants 全部 | Decoration（新建枚举值） |
| `Erase` | 擦除 | （占位类） | n/a |

> 关键决策：**新增枚举值 `Decoration` 和 `HandAuthored`**——前者标"装饰物不阻挡通行"，后者用于数据模型里区分"程序化生成" vs "手工建造"。
> 但要避免动 `TerrainType.cs` 引发连锁修改——见 §6 风险对策。

### 3.3 翻页控件

- 调色板右栏**显示 8 个一排**（对应原型图）
- 上下两个按钮 `◀ 上页` / `▶ 下页` 翻整页（按当前类别已注册的 prefab 数计算页数）
- 当前页索引显示在按钮之间 `(2 / 5)`
- 键盘快捷：`[ ]` 翻页、`Tab` 切换类别、`E` 切换擦除模式

### 3.4 放置交互

- 单击 prefab → 高亮选中（黄色描边）
- 鼠标移到地图格子 → 显示半透明 ghost 预览（仅渲染、可点穿）
- 单击格子 → 放置（替换该格的 prefab）
- **笔刷**：1×1 / 2×2 / 3×3 单选按钮
- **擦除模式**（选中 `Erase` 类别后）→ 单击格子清除
- **右击** → 吸管工具（拾取该格的 prefab 进调色板选中）
- **鼠标滚轮 + Alt** → 旋转预览相机

### 3.5 相机

- 等距相机参数固定（参考 `BattleScene` 主相机：orthographic, size 14, position `(11.87, 6.31, 10.87)`, rotation `(0.115, -0.881, 0.278, 0.365)`）——保证视觉与 BattleScene 一致
- 鼠标拖拽（Scene 视图标准 Orbit）+ 滚轮缩放
- 顶部工具栏"重置视角"按钮

## 4. 数据模型

### 4.1 新增 ScriptableObject `HandAuthoredMapData`

```csharp
[CreateAssetMenu(fileName = "HandMap_New", menuName = "Battle/Map Generation/Hand Authored Map")]
public sealed class HandAuthoredMapData : ScriptableObject
{
    public int Width = 16;
    public int Height = 14;
    public List<HandPlacedTile> Tiles = new List<HandPlacedTile>();
}

[Serializable]
public struct HandPlacedTile
{
    public int X;
    public int Y;
    public int Z;        // 高度层级（基础 0，桥/坡道 1）
    public string PrefabPath;   // 例 "Assets/Isometric Pack 3d/Props/Tile_Grass1.prefab"
    public float RotationY;     // 0/90/180/270
    public HandTileCategory Category;  // 决定运行时通行/不可达规则
}
```

`HandTileCategory` 枚举：
- `Base` `Forest` `Hill` `Mountain` `Water` `Bridge` `Road` `Building` `Decoration` `Erase`

### 4.2 运行时集成

`LevelMapGenerationProfile` 加一个字段：

```csharp
public HandAuthoredMapData HandMapOverride;
```

`ProceduralBattleMapProvider.CreateBattleMap` 里检测 `request.HandMapOverride != null` → 直接生成 `GeneratedMapData`（不用程序化）→ 走原有 placement/portal/validation 流程。

注意：**手工地图模式下，部署区规划/楼布置/传送门规划都得在手工地图上重新做**，所以 `BattleMapRequest.HandMapOverride` 还要携带"是否同时手工指定部署区/传送门"的子字段，缺这些时仍走自动规划。

### 4.3 持久化

工具右上角三个按钮：
- `新建`：创建 `HandAuthoredMapData` 并以临时 asset 形式放在 `Assets/ScriptableObjects/HandMaps/` 下
- `打开`：EditorUtility.OpenFilePanel
- `保存`：AssetDatabase.SaveAsset + 标脏

保存后 `HandAuthoredMapData.asset` 即可拖到 `LevelMapGenerationProfile.HandMapOverride` 字段里使用。

## 5. 实现步骤

按"先骨架后细化"的顺序，每步可单独跑通：

### 阶段 1：工具骨架（最小可跑）

1. 新建 `Assets/Editor/HandMapBuilder/HandMapBuilderWindow.cs`，菜单 `Tools/Map Generation/Hand Map Builder`
2. 窗口三栏布局：分类列表（左侧 ListBox）、3D 预览（中间 GameView 嵌入）、调色板（右栏 ScrollView 8 个一排）
3. 3D 预览：临时建一个空场景，相机按 BattleScene 参数摆好，加个 Plane 网格底图（10×10 灰色）
4. **门禁**：能打开窗口看到三栏布局就过

### 阶段 2：放置与数据模型

1. 写 `HandAuthoredMapData` + `HandPlacedTile`（在 `Runtime/Map/Generation/` 下，`Editor/` 工具代码引用）
2. 调色板**硬编码**挂 8 个 Isometric Pack 的 `Tile_Grass1-5` prefab 缩略图（用 `AssetPreview.GetAssetPreview`）
3. 点击格子放置：实例化 prefab 到预览场景对应坐标，存入 `_mapData.Tiles`
4. 撤销/重做：维护 `Stack<EditorAction>` 即可

### 阶段 3：分类翻页

1. 写 `PrefabCategory` 枚举（8 类）+ `PrefabCategoryConfig` 静态表（每个类别对应一组 prefab 路径）
2. 左栏 ListBox 切换类别 → 右栏调色板刷新成该类的 prefab 缩略图
3. 上页/下页按钮按"当前类的 prefab 数 ÷ 8"计算页数
4. 缩略图大小固定 64×64，一排 8 个

### 阶段 4：与 BattleScene 集成

1. `LevelMapGenerationProfile.HandMapOverride` 字段
2. `BattleMapRequest.HandMapOverride` 字段
3. `ProceduralBattleMapProvider.CreateBattleMap` 检测 HandMap → 直接生成 `GeneratedMapData`（每格 terrain 从 `HandTileCategory` 映射到 `GeneratedTerrain`，Ocean/ShallowWater/Plain 等）
4. 工具顶部"应用到 BattleScene 并运行"按钮，触发 `RandomMapToolWindow.ApplyToBattleSceneAndPlay` 的镜像流程

### 阶段 5：细化打磨

- 旋转：选中 prefab 后按 `R` 旋转 90°
- 笔刷大小 1×1/2×2/3×3
- 吸管工具（右击）
- 撤销/重做（Unity Undo 系统集成）
- 自动保存（每 30 秒存一次）

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 工具运行时视觉不一致（编辑器 3D，BattleScene 2D） | **已知妥协**——本阶段优先让手工地图可加载、可用；视觉切换留作 `3D等距地形替换与拓展方案.md` 的阶段 1 后续 |
| 同一格多次放置不同 prefab | 数据模型用 List 不去重，渲染时取最后一个；调试模式标红 |
| 桥/坡道的格子对齐 | tile FBX 实测 200×200cm（2×2 Unity 单位，缩放 0.5 对齐 1×1 格子），桥沿对角摆放，需要用户**手动对齐**——文档说明 |
| prefab GUID 在导入后变动 | `HandPlacedTile.PrefabPath` 用字符串路径而非 GUID，跨项目迁移友好 |
| 性能：40×40=1600 个 prefab 实例 | GameObject 总数 < 5000，Unity 编辑器可承受；运行时不实例化而是改 `BattleCellView` 后再实例化 |
| `TerrainType` 加值会动其他模块 | **不加枚举值**——用 `HandTileCategory` 独立的内部枚举；只在"工具 → 数据模型"间做映射 |
| 翻转地图（镜像）不支持 | 阶段 5 不做；后续按需扩展 |
| 存档太大 | 几千 prefab × 60 字节/条 ≈ 几百 KB，可接受；后续可压缩 |

## 7. 关键决策点（待用户确认）

1. **运行时视觉是否一起切换 3D**？最小方案：手工地图数据加载进 BattleScene 但运行时仍走 2D 渲染（用户能拼图、能跑游戏，但视觉不一致）。完整方案：先实施 `3D等距地形替换与拓展方案.md` 阶段 1，让 `BattleCellView` 支持 3D。
2. **部署区/传送门/楼房在手工地图上的策略**？最小方案：仍走自动规划（基于手工地形生成部署区、传送门、楼房）。完整方案：工具里加专门模式，让用户手工指定部署区和传送门锚点。
3. **存档格式**：纯 `HandAuthoredMapData` ScriptableObject vs 拆成多个（地形层 + 装饰层）？建议单文件 `HandAuthoredMapData`，便于编辑器和 BattleScene 共享。
4. **调色板默认分类页**：默认从 `Base` 开始还是 `Forest`？建议 `Base`。

## 8. 不做的事

- 不改 `TerrainType` 枚举
- 不动 `BattleCellView` 的 2D 渲染
- 不做实时多人协作（单人本地工具）
- 不做完整关卡编辑（仅地图地形/装饰，楼房和单位用现有自动系统）
- 不实现完整的 3D 地形运行时替换（那是另一个阶段的工作）

## 9. 验收标准

- 工具窗口能打开，左侧分类列表能切换
- 选 `Base` 类别，调色板显示草地/砖地 tile 缩略图，上页/下页可翻
- 点击 tile 缩略图再点地图格子，prefab 实例化到 3D 预览
- 保存后 `HandAuthoredMapData.asset` 能拖到 `LevelMapGenerationProfile.HandMapOverride`
- "应用到 BattleScene 并运行"启动 BattleScene，能加载手工地图跑游戏
- 撤销/重做正常工作
